# Plan: SPEC row data-encryption-keys (#1653)

## Objective

Deliver SPEC row `data-encryption-keys`: go-qrdb's DEK service reaches users
through `sdk/go`; QuicBaaS's own DEK store goes on the owner's word; the DEK
lifecycle, rotation, re-encryption and the safety interlock hold end to end.
The folded row #1841 (the tenant DEK lifecycle and `kms://` secret resolution
in the SDK, for go-trusted-platform) is part of this row. Detail:
`docs/data-encryption-keys/`.

## Slices, in order

1. **Fold the open slice PRs.** Merge PR #2377 (`fold/1841-tenant-dek-secrets`)
   and PR #2378 (`row/1841-secrets-error-cause`) with `--no-ff`, keeping both
   sides. Tests they bring: `sdk/go/qrdb_dek_reexport_test.go` (the tenant DEK
   request and response types are go-qrdb's), `sdk/go/secret_refs_test.go`
   (`kms://` references resolve through the SDK),
   `cmd/quicbaas/dek_tenant_test.go` (`quicbaas dek tenant` shows, rotates and
   retires the caller's keyring), `pkg/config/secrets/errors_test.go` (a
   resolution failure unwraps to its cause).
2. **`DEKClient` re-export.** `sdk/go`'s `DEKClient` is go-qrdb's `DEKClient`
   (a type alias, not a wrapper). Test: a compile-time identity test plus the
   per-transport verb tests already in `sdk/go/transport/*`.
3. **DEK lifecycle, rotation, re-encryption and the safety interlock.** The
   CLI and SDK drive create, rotate, set default, start re-encryption,
   progress, and set and clear the safety interlock on every transport. Tests:
   `make integration-test-dek` cases for each verb, including that rotation
   is refused while the interlock is set.
4. **QuicBaaS's own DEK store.** Mark it a parallel implementation in the
   docs; remove it only on the owner's word (not in this row without it).
5. **Ship the row.** Tick #1653's checklist and mark the row shipped in
   `docs/SPEC.md` in the row's one PR.

## Out of scope

- Removing QuicBaaS's own DEK store before the owner's word.
- KMS key management beyond what DEKs need (row `key-management`).
- Changes in go-qrdb itself.
