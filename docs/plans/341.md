# Plan: #341 REST user routes take a users:* grant, not tenants:*

## Objective

Every REST route under `/api/v1/tenants/{tenant_id}/users/` takes the grant
for the entity it operates on (a user, or a role assignment), never the
`tenants:*` grant it inherited from the first path segment. The grants match
MCP (`quicbaas_iam_*`, pkg/api/mcp/authz_qrdb.go) and gRPC
(pkg/api/grpc/authz_mapping.go), per ruling 161 (inherit, never invent) and
DS-1899 (qrdb vocabulary).

## Mapping

- User CRUD: `users:create` / `list` / `read` / `update` / `delete`
  (MCP `quicbaas_iam_user_*`).
- `POST …/roles`, `DELETE …/roles/{role}`: `roles:assign` / `roles:unassign`
  (MCP `quicbaas_iam_user_assign_role` / `_revoke_role`).
- Sessions: `users:read` / `users:update` (MCP `quicbaas_iam_session_*`).
- MFA: reads `users:read`; enroll, verify, challenge, backup-code issue
  `users:update`; factor removal `users:delete` (as WebAuthn credential
  deletion is on every transport).
- Account links: `users:read` / `users:update`; gRPC `LinkAccount`,
  `GetUserLinks`, `UnlinkAccount` move with them (iam.proto option + pb.go).
- GDPR: export and reads `users:read`; consent `users:update`; deletion
  request and cancel `users:delete`.
