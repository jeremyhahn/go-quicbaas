# Plan: #2231 an IP-address host needs an explicit WebAuthn rp_id

## Objective

When quicbaasd's `server.host` is a routable IP literal and
`iam.webauthn.rp_id` is not set, configuration validation fails at load
with a message naming `iam.webauthn.rp_id`, before any listener starts.
Before this change the node only failed later, in IAM initialisation, and
only when the qrdb client was available. The configuration docs state the
rule.

## Slices

1. Validator rule (one commit).
   - `pkg/config`: `WebAuthnIssuerHost(serverHost)` maps the wildcard and
     loopback hosts to `localhost`, the same mapping the issuer URL uses.
     `pkg/server.issuerURLFromConfig` calls it, so the mapping lives in
     one place.
   - `Validator.validateWebAuthnRPIDSource`: `rp_id` is empty and the
     mapped host is an IP literal → a `ValidationError` on
     `iam.webauthn.rp_id` that says to set it, or to use a hostname.
   - Tests (`pkg/config`): an IPv4 host and an IPv6 host with no rp_id
     fail and name `iam.webauthn.rp_id`; the same hosts with an explicit
     rp_id pass; loopback, wildcard and DNS hosts with no rp_id pass.
   - Docs: `docs/iam/architecture.md` (the derivation note) and the
     `rp_id` field comment state the rule; a changelog.d entry.

## Out of scope

- Changing the IAM-init gate in `pkg/server/iam_init.go` (it stays as a
  second line of defence).
- Per-tenant WebAuthn overrides (`settings.webauthn.rp_id`).
