# Plan: SPEC row software-factory (#1694)

## Objective

The Software Factory runs on QuicBaaS: projects, accounts and the SDLC
module on the engine; triage, task workers, review and merge on the
deployment; a standing MCP principal for every company agent; every
deterministic step of the manual factory (LSF runbook steps 0-13)
automated, with agents woken only for judgement. One branch, one PR; the
PR marks the row shipped in docs/SPEC.md.

## Slices (in order)

1. **Folds.** Merge PR #2466 (sdlc row: SDLC binding profile and public
   summary in docs/SPEC.md) and fold ref `row/805-aq805` (#805: pkg/sdlc
   and pkg/fleet under pkg/orchestration, guarded by
   `pkg/orchestration/sdlc/import_graph_test.go`). Tests: `make test-sdlc`,
   `make test-fleet`. Protected paths the fold touches
   (`.github/fips-compliant-packages.txt`, two workflow comments, the
   docs/SPEC.md D5 row) need the coordinator (LANE_POLICY_ALLOW).
2. **MCP principals (#1129, #1139).** An mTLS MCP principal per company
   agent in the automatethethings tenant, and custody of agent tokens,
   AI-account tokens and signing keys. Tests: IAM unit tests and
   `make integration-test-iam` on every transport.
3. **Parity: triage and brief (#2358, #2359).** Runbook steps 0-2 as SDLC
   module jobs. Tests: `make test-triage`, `make test-sdlc`.
4. **Parity: lanes, placement, seats, verify (#2360, #2361).** Steps 3-6.
5. **Parity: epic PRs, trains, CI, review, merge (#2362-#2364).** Steps 7-11.
6. **Parity: release, cleanup, status and tokens (#2365-#2367, #2375).**
   Steps 12-13, the status rollup, and progress-vs-spend tracking with
   baselines, alerts and budget stops.
7. **SDLC profile (#2368).** The artifact chain as a QuicBaaS SDLC binding
   profile.
8. **Approval gate (#2417).** External-issue approval with a per-project
   approver mode (human | triage agent | both).
9. **Exit gate (#2369).** One P1 project runs a full day on QuicBaaS with
   no LSF script; then docs/SPEC.md marks the row shipped.

Each slice adds the unit tests of the packages it touches (failing before,
passing after) and runs `make integration-test-<feature>` for each
feature it touches.

## Out of scope

- Renaming package identifiers (the #805 move keeps `sdlc` and `fleet`).
- go-qrdb and go-xkms changes: seams are consumed at their pinned tags.
- `changelog.d/*` history fragments that name the old paths.
