# Plan: #1683 SPEC row orchestration-volumes (folds #195)

## Objective

SPEC row `orchestration-volumes` (docs/SPEC.md): go-blockstore volumes in
container orchestration over the VolumeProvider surface (create, grow-only
resize, attach to a device path, promote/demote). Services declare volumes in
their manifest; the fleet node agent attaches them at launch. The NBD volume
store behind it: the boot node (go-trusted-platform, hosted by go-quicbaas as a
broker-class service) exports the volumes over NBD and diskless nodes take
their root and data volumes from it, through `sdk/go`. go-blockstore adds no
NBD code and go-quicbaas adds no NBD server.

## Dependency

`github.com/jeremyhahn/go-blockstore v0.4.0-alpha`, the newest tag whose
go-enclave requirement (v0.5.0) stays at or below the held pin v0.6.1-alpha
(#1389). v0.5.0-alpha needs go-enclave v0.8.0, so it waits for the #1389 bump.

## Slices

1. **Volume surface** (`pkg/orchestration/volumes.go`). Done: folded from
   the #195 lane, tests in `volumes_test.go`.
   - Aliases for go-blockstore's VolumeProvider, ReplicatedProvider, specs,
     statuses and error sentinels; `NewVolumeProvider` over its factory.
   - `VolumeClaim` with `Validate`; `VolumeAttacher`: Ensure (provision or
     grow), Resize (refuses a shrink before the provider), Attach (device
     path, host mount, bind `ContainerMount`), Release in reverse,
     Promote/Demote (ErrVolumeUnsupported without replication).
   - Tests: claim validation; provision-on-miss, reuse-on-hit, grow, no
     shrink; attach/mount order and mounts; rollback when a later claim
     fails; release order and carry-on; promote/demote on both fakes;
     factory rejects an unknown provider and settings key.
2. **SDK re-export**: done. `sdk/go/orchestration` aliases the provider,
   claim, attached-volume and attacher types, constructors and sentinels, so
   the boot node's NBD export consumes them through `sdk/go`. Test
   (`volumes_test.go`): the SDK types round-trip JSON with the server's.
3. **Launch wiring**: done. `ContainerSpec.Volumes`; `VolumeRuntime` wraps
   the node's runtime (outermost, so the resolved bind mounts are measured),
   attaches before Run/RunInteractive and releases on stop, remove and a
   failed start; any other runtime refuses unresolved volumes in Validate.
   `fleet.Config.Volumes` + `WrapVolumeRuntime` wire it into `fleet serve`.
   Tests: `volume_runtime_test.go`, `pkg/fleet/volumes_test.go`.

     orphan sweep, reaper and trust tiers see the inner runtime; teardown
     releases on not-found (`--rm`) and keeps what failed for a retry,
     serialised per container; rollback runs on its own bounded context, with
     a pending list retried before the next launch; a writable claim on an
     existing volume is re-Resized after mount (XFS grow); the local provider
     gets the node identity as `node_id`, a mismatch is refused. Tests:
     TestRuntimeAsWalksTheWrapperChain, TestVolumeRuntimeKeepsTrustCapabilities,
     TestVolumeRuntimeReleasesAfterContainerAlreadyGone,
     TestVolumeRuntimeRetriesAFailedRelease,

     TestVolumeAttacherAttachRollbackSurvivesCancel,

     TestVolumeAttacherToleratesAttachedResizeRefusal,

     TestRuntime_VolumeRuntimeKeepsOptionalCapabilities,

     TestWrapVolumeRuntimeTakesNodeIDFromSettings.
   - Review round 2: sandboxed spawn requests refuse a privilege class,
     devices and volumes, and the sandbox policy clears the class and devices;
     a volume has one owner per node (`ErrVolumeInUse`), recorded under the
     container's name and ID and persisted to `.quicbaas-attachments.json` in
     the staging dir; the reaper releases by name or ID and the startup sweep
     releases recovered volumes; a grow the provider refuses while detached

4. **Raw devices for the broker class**: done. `ContainerSpec.PrivilegeClass`
   and `Devices` (`--device`, measured only when set so other digests keep
   their value); Validate lets only `PrivilegeClassBroker` carry devices. A

6. **Coordinator + HA**: done (`volume_coordinator*.go`).
   `QRDBVolumeCoordinator` adapts go-qrdb's sdk Coordinator (lease held wraps
   `ErrVolumeLeaseHeld` and `*sdk.LeaseHeldError`; a missing key's delete is

   single-node fallback (mutex map, TTL leases on timers, watch fan-out), safe
   only within one process. `NewVolumeHAController` injects either into

   `volume_coordinator_test.go` (both coordinators, the HA controller
   promoting over the local one), the SDK's `volume_coordinator_test.go`.
