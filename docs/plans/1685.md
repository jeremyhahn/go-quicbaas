# Plan: SPEC row measured-launch (#1685)

## Objective

Every container launch is measured (image digest, config hash, policy hash)
into the node measurement log and the application PCR, under a signed cluster
manifest, with software-factory provenance as a signed DSSE referrer and
default deny (an audited allow-unsigned policy is recorded in the log).
Appraisal and reference values go through go-xkms; go-trusted-platform
supplies `HostTPM`. Folds: #1349, #1366. Detail: `docs/service-plane/`.

## Slices, in order

1. **Node measurement log and policy hash.** `pkg/orchestration`:
   `LaunchPolicy` and `LaunchPolicyDigest`; `LaunchMeasurement` v2 binds the
   image digest, config digest and policy digest; `MeasurementLog`, an
   append-only hash-chained log with `Verify` and `Replay`; the attesting
   runtime records each measured launch in the log in the same step as the
   `HostTPM.ExtendPCR`, so a failed extend leaves no entry and starts no
   container.
   Tests: measurement binds the policy; chain verifies and detects tampering;
   replay equals the PCR the fake TPM holds after N launches; a failed extend
   leaves the log unchanged.
2. **Log in the evidence.** `ContainerAttestation` carries the log entries;
   the Verifier replays them against the quoted PCR through `AppraiseQuote`
   and the reference-values store (no per-spec PCR list). Re-export
   `HostTPM`, `MeasurementLog` and `AppraiseQuote` in `sdk/go`.
   Tests: replay mismatch is refused; a forged entry is refused.
   As built: the log anchors each register at its first use (an `anchor`
   entry holds the value read from the TPM), so a restarted node agent whose
   PCR is already extended still replays; the Verifier's check is
   `launch-log` in `service.NewHostAppraiser`. `AppraiseQuote` was already
   in `sdk/go` (the attestation service client); the log API is re-exported
   in `sdk/go/orchestration`. The log is in memory; persisting it (go-qrdb)
   and carrying it in the gRPC `AttestContainerResponse` come with slice 5,
   which touches the generated code.
3. **Default deny and allow-unsigned.** A digest runs only if signed
   (go-xkms image verification), carrying provenance and listed in the
   reference values; an audited per-tenant/service `allow-unsigned` policy is
   folded into the policy digest and logged. Tests: unsigned refused;
   allow-unsigned admits, audits and appears in the log.
   As built: the gate is on the measured tier (`TPMAttestingRuntime`, options
   `WithImageVerifier` and `WithUnsignedImagePolicy`); a grant is keyed by
   trust label (`UnsignedImageGrants`), named in `LaunchPolicy.AllowUnsigned`
   (so in the measurement and the PCR), chained in the log entry and logged
   as an `AUDIT` warning. go-xkms v0.49.1 has no image-verification API, so
   `service.NewImageVerifier` runs the go-xkms attestation verifier (anchored
   chain plus signature over the digest) against a new `image-signer`
   endorsement kind. "Carrying provenance" lands with slice 4 and "listed"
   with slice 5. `NewTPMAttestingRuntime` has no production caller yet, so
   wiring the Verifier's image verifier into a node agent is with slice 5.
4. **Provenance as a DSSE referrer.** `pkg/sdlc` SLSA provenance signed via
   go-xkms, stored as a registry referrer; launch checks it (#1366).
   As built: `pkg/provenance` holds DSSE (PAE, envelope), the in-toto v1
   statement with the SLSA v1 predicate, and an OCI referrers client on
   image-spec types (go-containerregistry is not a dependency and go-xkms
   v0.49.1 has no DSSE API). Signing takes the factory key as a
   `crypto.Signer` (a go-xkms key); `sdlc.PublishImageProvenance` signs and
   pushes. `orchestration.ProvenanceVerifier` gates a signed measured launch;
   `service.NewProvenanceVerifier` verifies the referrer against the
   `image-signer` endorsements with the go-xkms attestation verifier, the
   same check the image signature gets. The provenance digest is not folded
   into the launch policy; the signature and the referrer are judged at
   admission. Calling the publisher from the merge train's image build waits
   on the in-repo registry and its referrers API (service-plane registry).
5. **Signed cluster manifest.** Signed list of service releases in go-qrdb;
   launch checks the release is listed.
   As built: `orchestration.ClusterManifest` (`WithClusterManifest`) gates a
   signed measured launch after the signature and provenance, refusing with
   `ErrReleaseNotListed`. `service.ClusterManifests` keeps one current
   manifest per tenant as a DSSE envelope in the Verifier's go-qrdb store
   (`provenance.SignPayload` signs it), anchored at a new `manifest-signer`
   endorsement kind and checked with the go-xkms attestation verifier on
   every read; versions must advance. A listing is by image repository and
   digest. Like provenance, the manifest version is judged at admission and
   not folded into the launch policy. The allow-unsigned path skips the
   listing. Still open from earlier slices: persisting the measurement log,
   the log in the gRPC `AttestContainerResponse`, and a production caller of
   `NewTPMAttestingRuntime` with the three verifiers wired in. A persisted
   log is valid only for the boot that recorded it (a reboot resets the
   PCR), so it must be keyed by boot (or dropped when the anchor read from
   the TPM no longer replays), and it must be written before the launch
   returns, or a failed write leaves the stored log behind the PCR.
6. **Moves from go-trusted-platform.** Golden values into the go-xkms
   reference-values store (one-time import), the attestation store into the
   go-xkms attestation results; container attestor moved in.
   As built so far: the container attestor is wired. `service.NewMeasuredLaunchRuntime`
   is the production caller of `NewTPMAttestingRuntime`: the host supplies
   its `HostTPM` (go-trusted-platform) and runtime through
   `MeasuredLaunchConfig`, and the Verifier side (host appraiser, image
   verifier, provenance verifier, cluster manifests) runs over the server's
   go-qrdb attestation store. `server.WithMeasuredLaunch` (re-exported in
   `sdk/go`) fills the `AttestContainer` seam with it; it is exclusive with
   `WithContainerAttestor`. Without a provenance source every signed launch
   is refused; without an allow-unsigned policy every unsigned one is.
   `AttestContainerResponse` carries `pcr_bank` and the node measurement log
   over gRPC, REST, the embedded transport and the SDK client. Still open:
   launching service containers (the orchestration sandbox runtime) through
   the measured runtime, persisting the log (keyed by boot, written before
   the launch returns), and the golden-value and attestation-store moves
   into go-xkms.
7. **Close-out.** Integration tests per feature, SPEC row shipped, sdlc.md.

## Out of scope

- go-trusted-platform's side of `HostTPM` (that repo implements it).
- Raw-TPM evidence checks (they move into go-xkms, not here).
