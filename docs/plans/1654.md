# Plan: SPEC row `kms` (#1654)

## Objective

Ship SPEC row `kms`: go-xkms KMS and its backends re-exported through
`sdk/go`, QuicBaaS's parallel key store kept until the owner removes it,
and every KMS verb scoped to the caller's tenant (another tenant's key,
policy or DEK id is not found, #1476). The row's one PR closes #1654 and
marks the row shipped in docs/SPEC.md.

## Slices, in order

1. Fold PR #2268 (#1768/#1772/#1783): generated symmetric keys carry
   Exportable into go-xkms and default to KeyTypeSecret; legacy
   encryption-typed symmetric keys stay reachable and cannot be shadowed.
   Tests: `pkg/kms/xkms_backend_legacy_type_test.go`,
   `pkg/service/kms_exportable_through_test.go`.
2. Fold PR #2279 (#2192/#2197): list and delete keys on xkms.v1;
   GenerateKey stays on quicbaas.kms.v1, the path that carries #2217's
   description, tags and owner. Done.
2b. #2196/#2128: one key namespace, CN=K TenantID=T, with the
   verified-ownership path for keys stored as `tenant/<t>/<k>`; a
   tenant-aware XKMSBackend metadata cache; removes the skip on
   `TestKMSNamespace_GenerateKeyUsesXKMSForm`.
3. Fold PR #2381 (#2165): REST ImportKey goes through the tenant-scoped
   KMS service.
4. Fold PR #2384 (SDK transports) and PR #2409 (#1793): KMS verbs over
   REST and QUIC accept their request types.
5. Remaining folded items, one slice each with a failing-first test:
   #136, #1572, #1782, #1794, #1833, #1934, #2111, #2125, #2197, #2217.
6. Row close: tick the checklist, mark the row shipped in docs/SPEC.md,
   `make integration-test-kms` green on every transport.

Each fold is `git merge --no-ff <head>` (no cherry-pick, no squash); its
tests must pass on the row branch.
