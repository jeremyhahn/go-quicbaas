# Plan: #721 — a test seam for pkg/iam's PBKDF2 work factor

## Objective

`go test -race ./pkg/iam` finishes well inside Go's default 10m budget on a
loaded runner, so pkg/iam no longer needs a bespoke race timeout. Today every
client-secret test issues and verifies at the production 600,000-iteration
work factor (`pbkdf2Iterations`, `pkg/iam/secret_kdf.go`), and `-race`
multiplies that cost.

Ruling 191 (DS-3821): take the issue's recommendation — option 1, the work
factor as a seam rather than a constant — bound by the testing guidelines.

## Design

- `pbkdf2Iterations` stays the production constant (600,000).
- New package variable `secretWorkFactor`, initialised to `pbkdf2Iterations`.
  Issuing (`deriveSecretHash`) and parsing (`parseSecretHash`) use it, so
  there is still exactly ONE accepted work factor per process: the
  non-enumeration property (every verification costs the same) holds
  unchanged.
- `timingEqualizerDigest` becomes a variable initialised from the constant
  `productionTimingEqualizerDigest`, so the equalizer always costs the same
  as a real verification at whatever factor the process runs.
- Only pkg/iam's own `TestMain` (`secret_kdf_workfactor_test.go`) writes
  either variable: it lowers the factor to 1,000 (the SP 800-132 floor, so
  FIPS-only runs still accept it) and derives an equalizer at that factor.
  No production code path, flag or environment variable can change it, so
  a stored hash is never verified at a weak factor in a server binary.
- Explicit-factor helpers (`deriveSecretHashAt`, `parseSecretHashAt`,
  `compareSecretHashAt`) let the KDF-specific tests still prove the
  production factor end to end, paying the 600k cost only there.

## Slices

1. Seam + tests (one commit):
   - `TestSecretWorkFactor_ProductionDefaultIsTheOWASPFactor`: the
     package-level default (captured before TestMain lowers it) is 600,000
     and the production equalizer parses at it.
   - `TestSecretWorkFactor_TestBinaryRunsAtTheTestFactor`: digests issued in
     the test binary carry the test factor, and the equalizer matches it.
   - `TestSecretWorkFactor_LowDigestNeverVerifiesAtProductionFactor`: a
     digest at the test factor is refused at the production factor.
   - `TestSecretWorkFactor_ProductionRoundTrip`: one issue+verify at 600k.
   - Existing work-factor tests compare against `secretWorkFactor`.
   - Makefile: drop pkg/iam's bespoke `IAM_RACE_TIMEOUT` comment/value to
     Go's 10m default, measured.

## Out of scope

- Other packages' tests that call `iam.HashClientSecret` still pay the
  production factor (they cannot reach the unexported seam).
- The shared `RACE_TIMEOUT` (30m) for the whole `race` target: other
  packages may rely on it; this lane only changes pkg/iam's own budget.
