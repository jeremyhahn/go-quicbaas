# Plan: #2516 acknowledged writes survive a crash

## Objective

The cluster integration suite ran with `QRDB_NOSYNC_WRITES=1`, and no test
checked that a write the server acknowledged survives a SIGKILL. This row
turns fsync back on for the cluster suite and adds two crash tests.

## Slices (in order)

1. `test/integration/docker-compose.cluster.yml`: drop `QRDB_NOSYNC_WRITES=1`
   (and its comment) from all four node services. The opt-in in
   `pkg/server/qrdb_node.go` stays.
2. Standalone SIGKILL test, `test/integration/durability/sigkill_test.go`:
   the test re-execs its own binary as a child (`TestSIGKILLChild`, gated by
   `QUICBAAS_SIGKILL_CHILD=<data dir>`) that boots the server with
   `bootServer`, writes 200 KV entities and 5 IAM users, prints `ACK <kind>
   <id>` per acknowledged write and blocks. The parent
   (`TestSIGKILLAcknowledgedWritesSurvive`) SIGKILLs the child after the last
   ACK, reboots over the same data dir in-process and asserts every
   acknowledged entity reads back with its value and every user exists.
3. Cluster SIGKILL test, `test/integration/cluster/sigkill_durability_test.go`:
   200 writes through the leader, `docker kill -s KILL` on the three voting
   containers at once, `docker start`, wait for a leader, assert every
   acknowledged ID is readable on each node. Containers come from
   `QUICBAAS_CLUSTER_CONTAINERS` (skip when unset); the Makefile
   `integration-test-cluster` recipe exports it.

## Out of scope

- Production code, the CLI and login routes.
- Running the Docker cluster locally (CI runs it).
