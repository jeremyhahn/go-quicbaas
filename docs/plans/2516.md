# Plan: #2516 acknowledged writes survive a crash

## Objective

The cluster integration suite ran with `QRDB_NOSYNC_WRITES=1`, and no test
checked that a write the server acknowledged survives a SIGKILL. This row
turns fsync back on for the cluster suite, adds two crash tests, and adds a
build gate that keeps fsync on.

## Slices (in order) — all done

1. `test/integration/docker-compose.cluster.yml`: `QRDB_NOSYNC_WRITES=1`
   dropped from all four node services. The opt-in in
   `pkg/server/qrdb_node.go` stays for local benchmarks.
2. Standalone SIGKILL test, `test/integration/durability/sigkill_test.go`.
   Proves: every write a single server acknowledged (200 KV entities, 5 IAM
   users) is on disk when the process is SIGKILLed. The parent
   (`TestSIGKILLAcknowledgedWritesSurvive`) re-execs the test binary as a
   child (`TestSIGKILLChild`, gated by `QUICBAAS_SIGKILL_CHILD=<data dir>`)
   that prints `ACK <kind> <id>` per acknowledged write; the parent SIGKILLs
   it, reboots in-process over the same data dir and reads every ACK back.
   Runs with `make integration-test-durability` (no Docker; CI runs it
   through `make integration-test`).
3. Cluster SIGKILL test,
   `test/integration/cluster/sigkill_durability_test.go`
   (`TestSIGKILLAllVotersAcknowledgedWritesSurvive`). Proves: with fsync on,
   200 writes the leader acknowledged survive `docker kill -s KILL` of all
   three voters at once; after `docker start` and a leader election (up to
   3m) every ID reads back on every node. Containers come from
   `QUICBAAS_CLUSTER_CONTAINERS` (skips when unset), exported by the recipe.
   Runs with `make integration-test-cluster`, whose go test timeout is
   raised from 300s to 900s to hold it.
   **Needs a Docker host and is not run by CI**: no workflow job runs
   `make integration-test-cluster`; whoever verifies runs it by hand.
4. Build gate, `test/buildgates/compose_fsync_test.go`:
   `TestIntegrationComposeFilesKeepFsync` walks every `docker-compose*.yml`
   under `test/integration` and at the repository root and fails, naming
   file and line, on any non-comment line that sets `QRDB_NOSYNC_WRITES`.
   `TestNoSyncLinesFindsTheOptIn` proves detection on a fixture. Runs in
   `make test`.

## Out of scope

- Production code (including the `QRDB_NOSYNC_WRITES` opt-in), the CLI and
  login routes.
- A CI job for `make integration-test-cluster` (no workflow change here).
