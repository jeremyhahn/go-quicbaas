# Plan: integration suite, main fix

## Objective

Make `make integration-test` green on main, one defect per slice, each
slice landing with the tests that prove it.

## Done slices

1. The cluster builder's clients act as the tenant operator; matrix cells
   log in as the first-boot admin and MCP liveness carries its session; the
   ceremony E2E's CLI trusts the CA chain first boot wrote.
2. MCP `data put` reaches quicbaas's entity KV tools, registered as
   `quicbaas_kv_put/get/delete/list` on the existing `kv:*` permissions;
   the SDK MCP transport targets them.
3. Sealed (shamir) init cells on grpc/unix and quic: a sealed node runs
   quicbaas's own sealed-window gRPC and REST listeners until unseal
   (`TestSealedBoot_GRPCServesQuicBaaSHealth`,
   `TestSealedBoot_QUICServesHealth`).
4. Review fixes: xkms key-name mapping and legacy key-name guard, tenant
   grace jobs, tenant ListJobs, AttestationService placement, MCP KV
   `shardID`. Main merged since.
5. `iam session revoke-all --keep-current` sends `--tenant`; the SDK
   `RevokeOthers(ctx, tenantID, keepSessionID)` puts `tenant_id` on the
   wire (`TestRunIAMSessionRevokeAll_KeepCurrent`,
   `TestSessionClient_RevokeOthers`). Fixes
   `TestCLISessionRevokeAllKeepCurrent`.
6. Barrier MCP 401 on `TestBarrierStatus/mcp/BarrierStatus` ("mcp
   transport: initialization failed: transport error: unauthorized
   (401)"). The node is not sealed in the integration run; the 401 came
   from the SDK. Over MCP, `Security().Barrier()` used go-qrdb's own MCP
   sub-client, which opens its own session without the platform bearer.
   Fixed in sdk/go/services.go: `Barrier()` returns the SDK MCP transport,
   which implements the qrdb `BarrierClient` and sends the bearer set by
   `WithAuthToken`, as REST and QUIC already do.
   `TestBarrierStatus_MCP_SendsPlatformBearer` (sdk/go) reproduces the CI
   error without the fix. No sealed-window MCP listener is needed; no
   server, MCP auth or permission change.

7. PR #2427 last review round (in progress): pkg/kms rolls back key
   material when its ownership record cannot be written; metadata probes
   derive from `SupportedAlgorithms` (restart coverage per algorithm);
   key IDs whose xkms name exceeds 255 characters are refused before any
   material (`ErrXKMSKeyIDTooLong` -> `ErrInvalidInput`); the SDK sends
   the `WithAuthToken` bearer on barrier verbs over gRPC and unix
   (`TestBarrierStatus_GRPCAndUnix_SendPlatformBearer`).

12. Slice 12, main fix: carries 91ab7eed7, 19cfb0c4d and 8b95da7e0
    (cherry-pick -x; the kms pick refuses an encoded-shaped literal key
