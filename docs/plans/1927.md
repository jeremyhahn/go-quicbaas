# Plan: #1927 — keep the generated administrator key out of JSON summaries

## Objective

`quicbaas init initialize --output json` must never print private key
material. Codex 7595 P1 1 (on #1845) found that once the go-qrdb pin bump
adds `AdminKeyPEM` (`json:"admin_key_pem"`) to
`CeremonyInitializeResponse`, the formatter encodes the whole response and
so prints the administrator private key to stdout.

## Where main stands

On main the pin is go-qrdb v0.30.1-alpha, whose
`CeremonyInitializeResponse` has no key field (`spki_pin`, `ca_cert_pem`,
`tls_cert_pem`, `state`, `share_count`). `--admin-generate` does not exist
yet. The defect returns with the pin bump (#1389/#1393), so this lane makes
the JSON path safe by construction before it lands.

## Slice 1 (this lane)

- `cmd/quicbaas/init_ceremony.go`: the JSON branch of
  `formatCeremonyInitializeResponse` encodes an explicit allow-listed
  `ceremonyInitializeSummary` (public fields only), never the raw response.
- Tests (`cmd/quicbaas/init_ceremony_summary_test.go`):
  - the JSON output holds exactly the public keys and their values;
  - a field guard: every JSON field of the pinned
    `CeremonyInitializeResponse` is either in the summary or on the
    secret deny-list (`admin_key_pem`). A new upstream field fails the
    test until someone classifies it, so the pin bump cannot silently
    widen the output.

## Out of scope

- `--admin-generate`, `--admin-key-out` and wiping the response's key
  bytes on every exit: the flag and the field arrive only with the pin bump;
  that lane wires the wipe and the generated-admin JSON regression test
  against the real field.
- go-qrdb / go-xkms changes.
