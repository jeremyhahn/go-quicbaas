# Plan: deployment values become configuration inputs (#2690)

## Objective

Values tied to one deployment (a registry address, host names, a
filesystem path, an operator address) stop living in the source. Each
becomes a configuration input or a public placeholder.

## Slices, in order

1. CI image registry. ci.yml reads the registry from a repository Actions
   secret in its three pull and three push steps. Each step fails when the
   secret is empty and masks the value before the cache script runs.
   Test: `test/buildgates/ci_image_registry_test.go` checks every registry
   step and checks that a mutated workflow is caught.
   `scripts/ci-image-cache_test.sh` still passes.
2. Ollama endpoint. `fleet serve` reads `OLLAMA_URL`. Precedence is a flag,
   then the environment, then the config file. The default stays loopback.
   Help text and review endpoint examples use the `inference.example`
   placeholder.
   Tests: `TestResolveServeConfig_OllamaURLPrecedence`, plus a review
   endpoint case that checks the placeholder appears in the error message.
3. CI comments. The cache-disk path and the GPU host name leave the ci.yml
   comments. No cache-root input is added, because nothing reads one.
4. verifygomodauth. The path of the decoy token file is a required input,
   `GOMODAUTH_TOKEN_FILE`, relative to the gate's throwaway HOME. The gate
   refuses a value that is unset, blank, absolute or escapes HOME.
   Tests: `TestDecoyTokenFileRefusesUnsetBlankAndNonLocal` and
   `TestRunRefusesWithoutTheTokenFile`.
5. Fixtures, docs and comments. A single scripted rename replaces the GPU
   host name and the operator address with neutral placeholders. The prose
   sites are then read again and fixed where the rename left them wrong.

## Out of scope

- code-review.yml and scans.yml.
- Any change to the Ollama default, or a cache-root input.
- A default for `GOMODAUTH_TOKEN_FILE`.
- Making pull-request runs that get no secrets pass the registry pull step.
  The owner rules on that.
