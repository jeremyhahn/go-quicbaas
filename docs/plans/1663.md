# Plan: SPEC row `attestation` (#1663)

## Objective

The attestation Verifier (quote appraisal against endorsements and reference
values, the endorsement and reference-values store, attestation results) is
go-xkms's. go-quicbaas re-exports it through `sdk/go` on all six transports,
consumes its results for admission, and owns no verifier, evidence check or
reference-values store. Folds: #1356 (Tier 1 launch check uses the re-exported
`AppraiseQuote`; `ContainerSpec.ExpectedPCRs` removed) and #1365 (attested
callers through go-xkms peergate, `WithAttestedCallerGate`, on the embedded node).

## Ordering (the row's own rule)

Bottom-up: the go-xkms Verifier SPEC row (go-xkms#1608) merges and ships in a
tag first; then go-quicbaas bumps its pin and re-exports. Files move into
go-xkms with their history; go-quicbaas never deletes and rewrites them.

## Blocker (slice 1, 2026-11-14)

The pinned go-xkms `v0.49.1-alpha` has no quote-appraisal Verifier service,
no endorsement or reference-values store, no `AppraiseQuote` and no peergate
(`pkg/attestation` holds key-attestation verification, `refvalue` signed
manifests and `peer` evidence checks only). The pin is also held by #1389
(the go-qrdb/go-xkms stack pin bump). No slice below can start until both clear.

Slice 2 (2026-11-14): the provider has shipped. go-xkms `v0.64.2-alpha` has
`pkg/attestation/appraisal` (`Appraiser`, `AppraiseQuoteRequest`,
`AttestationResult`, its `Store`) and `pkg/attestation/peergate` (`Gate`,
`Verifier`, `Collector`). It requires go-qrdb `v0.51+`, go-enclave `v0.8`
and go-quicraft `v0.22`, so it arrives only with the #1389 stack pin bump (a
separate train, rulings 247/250); this row does not bump the pin. The one wait
left is #1389 landing on main; slice 2 below starts on the merge of main after it.

## Slices, in order

1. go-xkms side (go-xkms repo, not this lane): move with history
   `pkg/orchestration/host_appraisal.go`, `pkg/service/host_appraiser.go`, the
   quote appraisal and quote-to-PCR binding of
   `pkg/orchestration/container_attestation.go`,
   `pkg/service/attestation_verifier.go`, `pkg/service/attestation_service.go`,
   `pkg/service/attestationtest`, and the `handlers_attestation` routes.
2. Pin bump to the go-xkms tag carrying #1608 (after #1389).
   Test: `go build ./...` and the unit tests of `pkg/service`, `pkg/orchestration`.
3. Re-export: `sdk/go` exposes the go-xkms Verifier; the REST routes
   (`/api/v1/attestation/verify`, `/verify-chain`, `/attest-container`,
   `/appraise-quote`, endorsements and reference-values CRUD) and every other
   transport serve the re-exported service. The moved files leave
   go-quicbaas (their history lives in go-xkms).
   Test: `make integration-test-attestation` on all six transports.
4. #1356: the Tier 1 launch check calls the re-exported `AppraiseQuote`;
   `ContainerSpec.ExpectedPCRs` removed. Test: a launch with a quote that
   fails appraisal is refused (fails before, passes after).
5. #1365: the embedded node gates callers with go-xkms peergate
   (`WithAttestedCallerGate`). Test: an unattested caller is refused, an
   attested one admitted.
6. Reference values as the approved-image registry: signed CoRIM under
   `attestation:provision`, cluster-replicated; docs/attestation updated.
7. Close: tick the row's items, mark the row shipped in docs/SPEC.md.

## Out of scope

- Any new appraisal or reference-values code in go-quicbaas (row rule).
- The go-xkms implementation itself, and the #1389 pin bump.
