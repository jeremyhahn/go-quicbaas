# Plan: hardware-backend-composition (#1664)

SPEC row `hardware-backend-composition`: device backend adapters are registered
in the QuicBaaS composition as the hardware crypto passed into go-xkms;
go-trusted-platform and xkey never import them.

## Where the composition is

`pkg/server/backend_resolver*.go` is the one place a configured crypto backend
becomes the `xkmssdk.ServiceBackend` that `startKMS` registers with go-xkms.
Each backend file registers a factory in `init()`; the resolver refuses a
backend whose factory is not compiled in (`BackendNotCompiledError`).

## Slices, in order

1. **trusted-firmware adapter** (this slice). go-xkms v0.49.1 ships it as
   `xkmssdk.NewAVRBackend` (`pkg/backend/avr`) over a trusted-firmware
   `tfw.Device`.
   - `pkg/config`: `BackendTypeAVR` (`avr`) is a valid backend; `kms.avr`
     (`device`, `baud`, `key_cn`, `request_timeout`); `kms.avr.device` is
     required when `kms.backend` is `avr`.
   - `pkg/server/backend_resolver_avr.go`: the tag-free `avr` factory opens
     the serial port, builds the go-xkms AVR backend and wraps it as the
     ServiceBackend; the backend's Close also closes the port it opened.
   - Tests: config accepts `avr` and rejects it without a device; the
     resolver resolves `avr`; the factory composes a ServiceBackend over a
     fake device that answers CAPS, reports type `avr`, and closes the port;
     an unopenable port and a silent device return `BackendConstructError`.
2. **SE052F adapter**: blocked until go-xkms ships an SE052F backend; then the
   same shape (config type, factory, tests).
3. **i.MX 95 adapter**: blocked until go-xkms ships an i.MX 95 (ELE) backend.
4. **Consumer**: go-trusted-platform reaches the device-backed keys through
   the QuicBaaS SDK (sdk/go KMS client) only; a test proves the SDK's
   dependency graph carries no device adapter import. Then the PR marks the
   row shipped in docs/SPEC.md.

## Out of scope

- Adding the adapters to go-xkms (they are go-xkms's own rows).
- CA signing-key storage on the AVR device (it holds one fixed key; no
  `StoreType`), and auto-detection of a serial device.
- `make integration-test-*` on real hardware: CI has none; the fake device
  stands in for unit tests.
