# #1652: SPEC row data-services

## Objective

Data services run on the one embedded go-qrdb node and reach callers
through `sdk/go` as go-qrdb's own clients (by alias), with no second store
and no QuicBaaS parallel data layer beside it (docs/SPEC.md row
`data-services`, detail `docs/data-services/`).

## Slices, in order

1. Fold `refs/fold/data-services/row/1904-aq1904` (done): the mixed
   read/write transaction test against a real qrdb node
   (`pkg/service/transaction_real_node_test.go`).
2. Re-export of go-qrdb's KV, batch, transaction, MVCC, collection and
   index services: `QRDBDataService` (the go-qrdb SDK client satisfies it)
   and `Client.QRDBData()` in `sdk/go`. Test: `sdk/go` routes each accessor
   to the go-qrdb client, and a KV put/get through `QRDBData().KV()` reaches
   the embedded go-qrdb servicer. CLI test mocks gain the method.
3. #2033: re-export go-qrdb's atomic write (conditional put) through the
   same surface. Test: compare-and-swap through `QRDBData().KV()`.
4. #1322: `Transaction().Execute` served on every transport (embedded type,
   gRPC/Unix route, REST/QUIC path, MCP tool), on go-qrdb's transaction.
   Test: the transport matrix test per transport, and the slice 1 test.
5. `storage.data_dir` derives `wal_dir`. Test: config load with only
   `data_dir` set yields `<data_dir>/wal`; an explicit `wal_dir` wins.
6. #1143 and "one datastore": every service on the one embedded node (the
   xkms `datastore:`). Test: a composition test that finds one store.
7. Removal of QuicBaaS's own data clients, storage backends, shards,
   leases, watch and routing: only on the owner's word (SPEC row text).
   Until then, no removal; this slice waits on that word.
8. Mark the row shipped in docs/SPEC.md in the row PR.

Each slice runs the unit tests of every package it touches and
`make integration-test-<feature>` of each touched feature.

## Out of scope

The go-qrdb pin bump (#1845) and the #1904 translation fix that waits on
it; anything not named by the row's acceptance or its folded items.
