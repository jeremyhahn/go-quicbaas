# #1891: an identity for hybrid embedded QRDB clients

## Objective

Codex 7420 P1 1 on #1845: `NewClient` must refuse a client configured
with `WithEmbeddedQRDB(...)` and no `WithEmbeddedIdentity(...)`, whatever
the transport. Today the check covers only `TransportEmbedded`, so
`WithREST()+WithEmbeddedQRDB(...)` builds an unbound qrdb sub-client.

## State of main (2026-11-13)

- main pins go-qrdb v0.30.1-alpha. The #1845 cut (the v0.51 bump) has not
  landed.
- main has no `WithEmbeddedIdentity`, `EmbeddedIdentity`,
  `NewEmbeddedIdentityRequired`, identity binder or `boundQRDBTransport`.
  They came in with the pin bump (5d4a7bf6a "both modules build on the
  bump", 160 files) and the #1814 commits after it (0b379374a, d0e99f6f4,
  067374d55, 7246451d5, 2b426f557). They exist only on `pr/1845` and
  `land/1845`.
- So the code the finding is about isn't on main, and re-landing it from
  the #1845 history means re-landing the go-qrdb pin bump. That work is
  #1845/#1814's, and the pin bump is held (#1389, #1816).

## Slices

   62615b30e (branch `issue/1814cf`):
   - In `NewClient` (`sdk/go/quicbaas.go`), require the identity when

     `WithEmbeddedQRDB(...)` without an identity fails with

   - Gates: the `sdk/go` unit tests with the rest/quic/mcp tags, and
     `make integration-test-<sdk feature>`.
