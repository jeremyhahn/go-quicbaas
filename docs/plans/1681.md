plan replaces the folded plan for #764. The folded `docs/plans/28.md` stays
until its SPEC row text is applied: the lane policy guard refuses

One row, one branch `row/1681-declarative-placement`, one PR; one slice per
lane session.

## Objective

An operator declares, per tenant, which hosts carry a role (agent, ci,
review): a host count or named hosts, with a measured resource profile. The
operator reads an exhaustive drift report of where the work runs. The
actuator moves fungible work back on its own, and anything else only on a
person's recorded consent. The verbs reach `sdk/go` on every transport and
the CLI.

## Departures from the design note

- P1 proves the lost edit on `NewMemoryTaskKV`'s guarded writes (the
  `PutIfAbsent`/`CompareAndSwap` contract the qrdb store serves), not on a
  `qrdbnode`; the store refuses a KV without those capabilities.
- The design's `workload_class` field is `role` in code, the owner's word.
- P2's finding kinds say host, not node (`host_not_admitted`, …,
  `role_unclassified`). `host_count_short` is added for the `host_count`
  field; `node_unrecorded` is gone, since hostless work is refused.
- `SessionRecord` carries no role yet (open question 2), so the session
  work source takes the caller's `SessionRoleFunc`.

## Out of scope

- Workload classes on `SessionRecord`, custody-session hand-off, the
  actuator's host and interval, and the permission names: open questions
  2 to 6 and 8 of the design note, for the owner or the CA.
- Any change to per-request host affinity routing (`host_affinity.go`).

## P3a progress (checkpoint)

Built: `FleetPlacementService` (`pkg/service/fleet_placement_service.go`) with
`DeclarePlacementSpec`, `GetPlacementSpec`, `ListPlacementSpecs`,
`WithdrawPlacementSpec` and `GetPlacementDrift`, bound by the server
(`pkg/server/fleet_placement.go`) to a spec store over the orchestration KV,
the shared fleet registry and the session store.

Departures:
- Verb names carry `Spec`/`Drift` because `PlacementService`, `GetPlacement`
  and `ListPlacements` already name the scheduler's placement engine.
- No new permissions: get, list and drift use `placement:read`; declare and
  withdraw use `placement:manage` (both already exist, admin and operator /
  admin only).
- The service is exposed through an optional `FleetPlacementProvider`
  interface, not a `QuicBaaS` method, so the ~15 test doubles need no stub;
  transports type-assert and answer 503 without it.
- Session role: a session with a recorded `HostAffinity` is `agent` work, a
  hostless one is governed by no spec (open question 2 still open).

Remaining in P3a: REST routes `GET|PUT|DELETE /api/v1/fleet/placements[/{name}]`
and `GET .../{name}/drift` (frozen permissions plus both goldens), REST tests
(`-tags rest`), SDK orchestrator client methods with REST and embedded
handlers, gRPC (proto, regeneration, server, authz map), docs/agent-fleet/api.md.
