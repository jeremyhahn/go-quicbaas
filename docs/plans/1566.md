# Plan: #1566 embedded ObjectStorage and ObjectTransfer stream verbs

## Objective

The embedded transport (`sdk/go/transport/embedded`) serves the four verbs
the `sdk/go` client calls and the route map lacks:

- `quicbaas.ObjectStorage/StreamPutObject` (client stream)
- `quicbaas.ObjectStorage/StreamGetObject` (server stream)
- `quicbaas.ObjectTransfer/FetchObject` (unary)
- `quicbaas.ObjectTransfer/StreamFetchObjects` (server stream)

Each handler delegates to the service the REST and gRPC transports use
(`ObjectStorageService`, `ObjectTransferService`) with the request and
response types the client sends and reads.

## Slices

1. Re-land the stream work from the deleted tip `issue/1562f`
   (commits 819170dc4 and 9dbc73692), rebased on main:
   - `handlers_objectstorage_stream.go`: StreamPutObject assembles the
     metadata message and ordered chunks into one `PutObject`, refusing an
     upload with no metadata or no last chunk (`IncompleteStreamError`,
     INVALID_ARGUMENT); StreamGetObject returns offset-ordered chunks;
     StreamFetchObjects returns one response per requested object;
     FetchObject is unary and typed, a nil service response is
     `EmptyServiceResponseError`.
   - Route keys in `transport.go` (`unaryHandlers`, `streamHandlers`).
   - Tests (`handlers_objectstorage_stream_test.go`,
     `handlers_objecttransfer_fetch_test.go`): for each verb, the real
     client call through the embedded transport and its result, and the
     error path (missing object, bad input, service not configured).
2. One changelog entry, `changelog.d/1566-embedded-object-streams.md`.

## Out of scope

- The gRPC transport commits of #1625/#1621 and the client-side stream
  writer fix of `issue/1562d` (2c752a44c); a client defect found on the
  way goes in the report.
