# Plan: #203 interop legs against our wire surfaces

## Objective

Every compatibility claim go-quicbaas writes about HTTP/3, OIDC/OAuth2, gRPC
and MCP is either enforced by a test that drives our server with an
independent client implementation, or narrowed to what is true. Those legs
run in their own integration-tier CI job (not per push), one job per external
implementation, each proving a healthy baseline before its operations.

## Already on main (earlier lanes of the epic)

- Claims audit: `docs/multiprotocol-api/engineering.md`, "Interop claims audit".
- OIDC/OAuth2 leg: `pkg/api/rest/oidc_interop_test.go` (x/oauth2, jwx) and
  `pkg/api/rest/oauth2_interop_test.go` (x/oauth2, go-jose, RFC 7009).
- HTTP/3 leg: `pkg/api/rest/http3_interop_test.go` (quic-go `http3.Transport`).
- gRPC leg: `pkg/api/grpc/interop_connect_test.go` (connect-go, gRPC mode).
- MCP leg: `pkg/api/mcp/interop_official_client_test.go` (official MCP Go SDK).

Until this slice, those legs ran only inside the per-push unit suite, mixed
with everything else: no job named an external implementation, and nothing
showed a baseline passing before the operations.

## Slices

1. **Interop legs as their own target** (this slice). `.github/workflows/`
   is a protected path for the lane, so the legs live in
   `scripts/interop-legs.sh` (the leg table: oidc, http3, grpc, mcp) behind
   `make interop-test` and `make interop-test-<leg>`. Each leg runs its
   baseline test alone first, then every test of the leg. A leg fails on a
   failing test and on a pattern that runs no passing test, and prints an
   `INTEROP-FINDING` line. Test: `test/buildgates/interop_legs_test.go` fails
   when a surface has no leg, a baseline does not select exactly one test, a
   leg selects nothing beyond its baseline, a make target is missing, or the
   script lets a vacuous or failed baseline pass. The claims audit names the
   targets.
2. **Batch job wiring** (needs a holder of the workflow path). Add to
   `.github/workflows/batch.yml` an `interop` job with a matrix over
   `leg: [oidc, http3, grpc, mcp]` that runs `make interop-test-${leg}`,
   and add `interop` to the `jobs` input's choices.
3. **Wire mutation proof.** On a scratch branch, break each surface (drop
   S256 from discovery, refuse `h3`, change a gRPC status, rename an MCP
   tool) and run the leg: it must fail. Done locally per leg; the result
   goes in the PR body, the mutation is not committed.

## Out of scope

- External *binaries* (curl with HTTP/3, grpcurl, a non-Go gRPC client):
  ubuntu-latest's curl has no HTTP/3 and grpcurl is grpc-go underneath;
  each needs a pinned tool per devops.md §9 and is a follow-up slice.
- The legs drive the routers on loopback listeners, not go-qrdb's unified
  listener; the audit says so per leg.
- MySQL/PgSQL wire compatibility is go-qrdb's to test.
