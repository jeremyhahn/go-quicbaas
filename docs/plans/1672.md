# Plan: SPEC row `rag` (#1672), RAG through go-qrdb

## Objective

Ship the SPEC row `rag` (docs/SPEC.md, detail in `docs/rag/`): go-qrdb's
RAG service re-exported through `sdk/go` as `RAGClient`; QuicBaaS's own RAG
pipeline kept as a parallel implementation until the owner says to remove
it; chunking, ranking and context assembly. The row's one PR also closes
the folded items #549, #1611 and #2067, accounts for every `refs/fold/rag/`
ref, and marks the row shipped in docs/SPEC.md.

## Slices, in order

1. **Fold and test reach (this slice).**
   - Merge `refs/fold/rag/row/549-aq549` (#549: drop the unread
     `watcher.Config.DebounceDelay`); its `TestConfig_NoDebounceDelayField`
     proves the knob is gone.
   - #2067: `make test-rag` passes `-tags '$(TEST_TAGS)'` on all three
     lines, so the rag-tagged watcher tests and the REST/MCP RAG tests run.
     Test: `scripts/resolve-package_test.sh` (`make check-package-targets`)
     asserts the tags on each `make -n test-rag` line; it fails before.
   - Fix whatever those tests show once they run.
2. **go-qrdb `RAGClient` re-export: built, then removed.** The node never
   serves go-qrdb's RAG service, so the re-export (`sdk/go/qrdb_rag.go`)
   could reach only a separate go-qrdb node, which docs/SPEC.md forbids.
   It is deleted with its tests and docs; `Client.RAG()` is the SDK's RAG
   surface. Serving go-qrdb's RAG from the node is go-qrdb work, reported.
3. **#1611: one RAG service method (done)** shared by REST, MCP, gRPC and the
   embedded client: `pkg/rag/ragservice`. The node now serves gRPC
   `RAGService` (it was generated but never registered) and the embedded
   transport gains `quicbaas.RAG/*` routes under the `rag` tag. Tests: each
   transport's handler test checks its output against the shared method's
   for the same request, and that its error codes match
   (`pkg/api/grpc/server_rag_test.go`,
   `sdk/go/transport/embedded/handlers_rag_test.go`,
   `pkg/server/lifecycle_rag_grpc_test.go`). `make test-rag` runs them all.
4. **Chunking, ranking and context assembly (done)**, audited against
   `docs/rag/`. Ranking: `VectorWeight` and `KeywordWeight` were never
   read, so hybrid fusion is now weighted RRF, and ties order by ID
   (`pkg/rag/ranking/fusion_weight_test.go`). Context: dropping results
   past `MaxResultsPerChunk` now sets `Truncated`
   (`TestBuilder_Build_MaxResultsPerChunk`). Chunking matched the docs,
   apart from one point now documented: a Go function longer than
   `chunk_max_tokens` stays one chunk, marked `too_large`.
5. **Review fixes.** The SDK gRPC RAG handler calls the generated
   `RAGServiceClient` (round-trip test on bufconn against the real server);
   `min_score` carries presence, so an explicit 0 disables the filter
   (MCP test); `make test-rag` runs the MCP handler tests. The gRPC
   RAGService logs a server-side failure and returns a stable message, not
   the backend's (`TestRAGServer_BackendErrorIsNotReturned`); the SDK handler
   round trip against the real server checks min_score 0.5 / explicit 0 /
   omitted and the status code of a backend failure
   (`rag_handler_roundtrip_test.go`).
6. **Ship:** docs/SPEC.md row marked shipped only once `sdk/go` re-exports
   go-qrdb's `RAGClient`; until then it stays `in progress`. Changelog
   fragment, the issue's checklist ticked.
