# Plan: #1779 ci: fail when sdk/typescript/dist differs from a tsc build of src

## Objective

CI fails when the committed `sdk/typescript/dist` is not what `tsc` builds
from `sdk/typescript/src`. CI already runs `make test-sdk-ts`, so the check
hangs off that target and needs no workflow change.

## Slices

1. `make check-sdk-ts-dist` (Makefile), a prerequisite of `test-sdk-ts`:
   - `npm ci` (via `install-sdk-ts`), then `rm -rf dist` and the package's
     own `npm run build` (`tsc`);
   - fails when the built dist differs from the dist in git's index:
     `git diff --name-status` (changed or deleted files; a stale file whose
     source is gone shows as deleted) plus untracked files tsc emits, and
     names each drifted file.
   - Tests (`test/buildgates/sdk_ts_dist_test.go`, run by `make
     test-tooling`): the target's recipe runs in a temporary git tree with
     a fake `npm` whose build copies `src/*.ts` to `dist/*.js`:
     - a dist that matches its build passes;
     - a hand-edited committed dist file fails and is named (only it);
     - a missing output and a stale file both fail and are named.
   - Manual checks: on a clean tree `make check-sdk-ts-dist` passes; with a
     hand-edited, staged `dist/accounts.js` it fails naming that file.

## Out of scope

- Any change to `sdk/typescript/src`, `tsconfig.json` or the build script.
- The other npm packages (`sdk/javascript`, the frontend): no committed
  build output is checked there.
