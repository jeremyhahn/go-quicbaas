# Plan: #1846 embedded IAM User List and Role List honor the client page size

## Objective

The embedded transport's `handleIAMUserList` and `handleIAMRoleList`
(`sdk/go/transport/embedded/handlers_iam.go`) asserted a bare
`*ListUsersRequest` / `*ListRolesRequest`, but the real client sends the
`listUsersRequestInternal` / `listRolesRequestInternal` wrapper. The page size
was silently dropped and every list returned the whole tenant. Same root cause
as #1814.

## Slice 1 (this lane)

- Both handlers unwrap the client's request with `iamRequestStructPtr(req,
  "Request")`, as the Role Create/Update and Policy List handlers do; a bare
  request is still accepted.
- The page token is the decimal offset of the next item, as the embedded
  vector ListNamespaces uses; a malformed token is refused with
  `InvalidPageTokenError`. The handler asks the store for one item more than
  the page size to fill `Pagination.HasMore` and `NextPageToken` without an
  empty trailing page. Without the token the issue's "next page continues
  correctly" cannot hold.
- `iam.MemoryStorage.ListRoles` sorts by ID before it applies the offset,
  as its `ListUsers` already does: map order made offset pages overlap.
- Tests (`handlers_iam_list_page_test.go`), through `embedded.New` and the
  real `iamsdk.NewUserClient` / `NewRoleClient`:
  - a list with page size N returns at most N items, and following
    `NextPageToken` visits every item exactly once, ending with no token;
  - a malformed page token is refused;
  - both fail before the fix (page size ignored, no token).

## Out of scope

- Any other handler, the REST/QUIC/gRPC transports, the persistent stores' ordering.
