# #2365: the factory owns releases

## Objective

The factory cuts alpha, staging and production tags only from a green main,
cuts a production tag only with an owner's authorization naming the tag and
the commit, and runs and reports a consumer check against each release.

## Slices, in order

1. **Release gate (pkg/sdlc/release.go).** `EvaluateReleaseGate` refuses, in
   order: a tag that is not `vMAJOR.MINOR.PATCH[-pre]` (or a commit that is
   not a full SHA), a tag whose pre-release does not suit the kind, a tag
   that already exists, a main that is red, running or unchecked, and a
   production release with no `release-authorized: <tag> <sha>` line from a
   ruler on the release issue. `NextAlphaTag` mirrors the Makefile's
   release-alpha bump. `ReportConsumerCheck` posts the consumer check once,
   under a marker. `ReleaseGate.Evaluate` reads the tag, checks and comments
   from the forge.
   Tests: `TestEvaluateReleaseGate_*`, `TestNextAlphaTag`,
   `TestReportConsumerCheck_*`, `TestReleaseGate_EvaluateReadsTheForge`.
2. **Tag creation.** A `CreateTag` forge verb on every adapter, verified by
   read-back, cut only after the gate allows. Tests: adapter wire tests and
   a gate-then-tag test on the fake forge.
3. **Release job.** A job that reads main's tip, evaluates the gate, tags,
   runs the consumer check and reports it on the release issue; the Makefile
   `release-alpha` target calls it instead of tagging by hand. Tests: the
   job end to end on the fake forge, and the integration target.

## Out of scope

- Publishing artifacts (binaries, images, module proxies) beyond the tag.
- Changing which logins count as rulers.
