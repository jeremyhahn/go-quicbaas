# Plan: SPEC row `transparency-log` (#1675, folds #1341)

## Objective

go-quicbaas appends its own records to go-xkms's transparency log and
re-exports it through `sdk/go` on every transport, with the tenant's
isolation. The seam is built bottom-up: go-qrdb's verifiable log → go-xkms's
transparency log → the go-quicbaas appender. go-quicbaas has no log, Merkle
tree or proof code of its own.

## Seam status (checked 2026-11-14, re-checked 2026-11-21)

On 2026-11-21 the proxy's newest go-xkms tag was still v0.64.2-alpha, and its
`docs/transparency-log/engineering.md` still says that the log, the append
verbs and `HeadSignerProvider` "are not on main". go-quicbaas's pins are
still held by #1389.

| Layer | Where | State |
|---|---|---|
| go-qrdb verifiable log (`vlog`) | go-qrdb v0.58.x (`pkg/api/grpc/service_vlog.go`, `cmd/qrdb/bindings_vlog.go`) | released |
| go-xkms checkpoint format | go-xkms `pkg/ca/checkpoint`, `sdk/go/checkpoint` (v0.64.2) | released |
| go-xkms transparency log, append verbs, `HeadSignerProvider` | go-xkms `docs/transparency-log/engineering.md`: "not on main" (main ec11e34, 2026-11-13) | **missing upstream** |
| go-quicbaas pins | go-xkms v0.49.1, go-qrdb v0.30.1 | the stack bump to xkms v0.64.2 / qrdb v0.51+ is blocked on go-libsignal (go-enclave v0.8) |

The row cannot be delivered until go-xkms releases its transparency log.
Writing the log here would break the row's third acceptance line.
Slices 2-5 (every code slice) hold until go-xkms publishes the transparency
log; this PR is the plan only and carries no pin bump.

## Slices, in order

1. **Plan** (this slice): this file. No code.
2. **Pin bump** (it needs go-xkms with the transparency log tagged, plus the
   go-libsignal release): move go-xkms, go-xkms/sdk/go and go-qrdb to the
   exact released tags in both go.mod files (root and `sdk/go`). Tests: the
   existing unit and integration suites stay green.
3. **Appender**: a `pkg/transparency` adapter that turns go-quicbaas's own
   records (the event kinds the go-xkms API defines) into go-xkms append
   calls in the caller's tenant. It only calls go-xkms. Tests: append, then
   inclusion proof verifies; tenant A's entries are invisible to tenant B;
   a cross-tenant append is denied.
4. **SDK re-export**: `sdk/go` re-exports the go-xkms transparency-log
   client (type aliases and `var` assignments, so `errors.Is` matches) on
   all six transports (REST, gRPC, QUIC, MCP, Unix, embedded), including
   the MCP tools for append, proofs and tree heads. Tests: a transport-matrix
   test over the same six, MCP included (append, get inclusion and
   consistency proofs, verify a signed tree head) and an `apimodule`
   re-export test.
5. **Integration and close**: `make integration-test-transparency-log`
   drives the CLI end to end on REST, gRPC, QUIC, MCP, Unix and embedded.
   Mark the row shipped in docs/SPEC.md, tick #1341, and add
   `docs/transparency-log/` (pointing at go-xkms's docs).

## Out of scope

- Any Merkle tree, proof, checkpoint or log storage code in go-quicbaas.
- Changes to go-qrdb or go-xkms. Those are their own rows; this row only
  consumes released tags.
