# Plan for #2485: the KMS Sign verb takes an RSA-PSS padding option end to end

#2485, a caller using an RSA key through the SDK `crypto.Signer` with `*rsa.PSSOptions` gets a PKCS#1 v1.5 signature, because SignRequest has no padding field.

## Planned change

api/proto/kms.proto gains `SignaturePadding` and SignRequest fields padding=5, pss_salt_length=6, mgf1_hash=7 with only api/proto/kms.pb.go regenerated; pkg/service SignRequest gains Padding, PSSSaltLength, MGF1Hash with validation in `validateSignRequest` and a PSS branch in `cryptoService.Sign` through a new optional `interfaces.PSSSigner`; `KMSService.SignPSS` and `XKMSBackend.SignPSS` sign RSA keys with `rsa.PSSOptions`; gRPC server and client, REST handler, SDK crypto client, SDK re-exports and `QuicBaaSSigner` (via `signRequestForOpts`) carry the option; new tests in pkg/kms, pkg/service, pkg/api/grpc, sdk/go/client/crypto and sdk/go; docs/plans/2485.md.
