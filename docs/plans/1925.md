# Plan: #1925 Batch Execute on every transport

## Objective

Serve `SDK().Batch().Execute` on REST, gRPC, QUIC, MCP and Unix, each under
`batch:execute`, as one atomic `service.BatchExecute` (qrdb `ExecuteBatch`)
per request, with the typed refusals `service.BatchExecute` returns.

## Base

`service.BatchExecute` and the REST, MCP and embedded slices already live on
`issue/i1533g` (epic #1533 / #1537, rebased on main 2026-11-13). This row
merges that branch instead of redoing it, so the two cannot conflict at train
time. The gRPC slice from the older `issue/i1533h` (2026-10-30) is ported
onto it.

## Slices, in order

1. Merge `issue/i1533g`: service `BatchExecute`; REST
   `POST /api/v1/batch/execute`; MCP `quicbaas_batch_execute`; embedded.
   Tests: `pkg/service/batch_execute_test.go`,
   `pkg/api/rest/handlers_batch_execute_test.go`,
   `pkg/api/mcp/tools_batch_execute_test.go`, SDK REST/MCP handler tests.
2. gRPC server: a `BatchExecute` RPC in `api/proto/quicbaas.proto` under
   `batch:execute`, served by `pkg/api/grpc/server.go` (regenerate `pb.go`).
   Tests: server converter unit tests.
3. gRPC SDK transport: `kv_handler.go` routes `quicbaas.Batch` `Execute`.
   Tests: `sdk/go/transport/grpc/batch_handler_test.go` (put and delete batch,
   bad request refused).
4. QUIC (built on REST) and Unix (built on gRPC): one test each, sending a
   put and delete batch through the SDK client, plus a refused bad request.

## Out of scope

- New batch verbs other than Execute, and streaming batch.
- Changes to the CLI.
