# Plan: #23 — the audit HMAC signing key lives in protected storage

## Objective

The audit-log HMAC signing key (`pkg/security` `AuditConfig.SignKey`,
`AuditLogger.signKey`) is never a plain Go `string` or `[]byte`. Ruling 189
(DS-3821): at this layer use the owned surface (quicbaas KMS / qrdb credential
support), never a raw locked-memory wrapper.

## Design

- `AuditConfig.SignKey` becomes `*secret.SecretValue` (the quicbaas SDK
  re-export `sdk/go/secret` of go-qrdb's config-time credential-resolution
  target). The `sign_key` JSON/YAML key keeps its shape: it decodes the
  reference (`credential://…`, `kms://…`, env) into the value, and the config
  processor (`pkg/config/secrets`) seals the resolved key into the value's
  enclave. It never rests in a Go string.
- `NewAuditLogger` reads the key only through `WithBytes`, so the length
  check runs on mlocked memory. It seals its own copy (`secret.NewSecretValue`)
  so the logger owns that copy's lifetime. An unresolved or empty value
  fails as `AUDIT_SIGN_KEY_REQUIRED`. A key shorter than `MinAuditSignKeyLen`
  fails as `AUDIT_SIGN_KEY_TOO_SHORT` (#12's check moves onto the protected
  path).
- `signEvent` computes the HMAC inside `WithBytes`; no plaintext key field
  stays on the logger. `Close` clears the logger's copy (`Clear`), after which
  signing fails closed.

## Slices

1. This plan.
2. `pkg/security/audit.go` + tests:
   - a test that `AuditLogger` has no `string`/`[]byte` key field and that
     `AuditConfig.SignKey` is a `*secret.SecretValue` (reflection; fails
     before, passes after);
   - JSON decode of `sign_key` keeps the reference, never the plaintext,
     when marshalled again;
   - an unresolved reference is rejected; empty/short keys are still rejected;
   - signing after `Close` fails closed (the enclave is destroyed);
   - the existing signing tests move to a `testSignKey(t, s)` helper.
3. Docs: `docs/audit-logging/engineering.md`, `docs/security-hardening/*`,
   and a changelog fragment (the Go field type changes for callers).

## Out of scope

- Delegating HMAC to a KMS backend per event (Q3 is settled: in-process).
- `crypto/hmac` derives its pads from the key on the heap for the length of
  one `Sum`; the stdlib gives no zeroing hook. That state is transient and
  short-lived. It is not a retained copy.
- #18 (#12's minimum length) is already on `main` (`MinAuditSignKeyLen`);
  this change carries the check, it does not duplicate it.
