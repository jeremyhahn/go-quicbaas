# Plan: #764 declarative placement, drift report, consent-gated actuation

Design: [docs/agent-fleet/placement.md](../agent-fleet/placement.md). Slice P0
(every `RequiredCapabilities` entry is a hard match in `matchFleetNodeForTask`)
has landed. This row builds the rest, one slice per lane session.

## Objective

An operator declares where a class of work may run (a `PlacementSpec` per
tenant), reads an exhaustive drift report of where it actually runs, and the
actuator moves fungible work back on its own and everything else only on a
person's recorded consent.

## Departures from the design note

- P1 proves the lost edit on the in-memory KV's guarded writes (the same
  `PutIfAbsent`/`CompareAndSwap` contract the qrdb store serves), not on a
  `qrdbnode`; the store refuses a KV without those capabilities.
- The unnameable-work refusal error is defined in P2 with the rule it enforces.

## Out of scope

- Workload classes on `SessionRecord`, custody-session hand-off, the
  actuator's host and interval, and the permission names: open questions 2–6
  of the design note, for the owner or the CA.
- Any change to per-request host affinity routing (`host_affinity.go`).
