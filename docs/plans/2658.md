# Plan: #2658 gRPC user lookup (GetByEmail, FindByUsername)

## Objective

The Go SDK serves `UserClient.GetByEmail` and `UserClient.FindByUsername`
over the gRPC transport, backed by a `GetUserByUsername` RPC; both lookups
require users:read.

## Slices, in order

1. `GetUserByUsername` gRPC RPC on IAMService with GetUser's authorization
   (done, 184a6f29a). Tests: pkg/api/grpc authz and adapter tests.
2. SDK `GetByEmail`/`FindByUsername` over the gRPC transport (done,
   e894c2b3d). Tests: sdk/go/transport/grpc iam_user_audit_parity_test.go
   `TestIAMUserGetByEmail_*`, `TestIAMUserFindByUsername_*`.
3. Review fix (PR #2670): `GetByEmail` refuses an email without "@" with
   InvalidInput in the client (sdk/go/client/iam/user.go) and in the gRPC
   handler `handleGetUserByEmail`, before any server call. The server's
   GetUser routes an id without "@" to a numeric user-ID lookup, so
   `GetByEmail("30001")` returned user 30001. Tests:
   `TestIAMUserGetByEmail_NumericInput` (client and transport subtests,
   zero server calls) and a "no @" case in `TestUserClient_GetByEmail`.
4. Review fix (PR #2670): under RequireAuthz both lookups were default-denied
   even for users:read. GetUser and GetUserByUsername now take users:read
   (as QRDBService's user reads do) in iam.proto and authz_mapping.go.
   Tests: `TestIAMUserLookupGRPCAuthorization` (users:read allowed,
   users:list denied) and `TestIAMUserLookupGRPC_ThroughGate` (real handler
   behind the interceptor; a foreign tenant is refused with no lookup).

## Out of scope

- RFC email parsing; the check is "contains @" only.
- Any change to the server's GetUser routing.
- Mapping any other IAMService method.
- go.mod/go.sum changes.
