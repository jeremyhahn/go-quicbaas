# Plan: #1414 IAM CreatePolicy presence-tracked `enabled`

## Objective

`CreatePolicyRequest.enabled` becomes proto3 `optional bool`. If it is absent,
the policy is enabled. Explicit `true` enables it. Explicit `false` with rules
stores the policy disabled, and go-qrdb's evaluator then skips it. Explicit
`false` with no rules is refused with `ErrPolicyInvalid`. This holds on gRPC,
REST, MCP, QUIC, Unix and embedded, and in SDK `client/iam` on every transport.
The design is CA m323 item 5 (b): go-qrdb carries `enabled`.

## Status: blocked on the go-qrdb pin

- Main pins go-qrdb v0.30.1-alpha (`go.mod`, held by #1389). Its
  `abac.PolicySpec` has no `Enabled` field. The field arrived in go-qrdb#757,
  which is in v0.51.0-alpha.
- #1389, the stack bump, is blocked upstream: go-libsignal v0.3.1 still calls
  `MemoryEnclave.Open`, which go-enclave v0.8 removed.
- The existing work, 94e84687d (issue/1410a-policy-enabled-presence),
  cherry-picks onto main 34272658b without a conflict. The only build error
  is `pkg/server/abac_sync.go:296: unknown field Enabled in
  sdk.ABACPolicySpec`.
- Landing without that line would store a "disabled" policy that go-qrdb
  still enforces. Dropping disabled policies from the sync quicbaas-side is
  option (a), which m323 rejected. So this lane does not land a partial
  change.
