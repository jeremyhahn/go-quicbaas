# Plan: #772, the scoped FIPS gate back on the push path

## Objective

Owner-approved SPEC #1299, security-hardening row: "The scoped FIPS gate
runs on push". Main's #114 ruling (2026-08-23) put a scoped, required
`GODEBUG=fips140=only` job in `ci.yml`. The main→feature merge (#768) left
FIPS in `nightly.yml` only. This row puts the scoped gate back in `ci.yml`
and in CI Gate. The full, unscoped run stays nightly.

## Slices

1. **The gate.**
   - `Makefile`: `test-fips-gate` runs the root module under
     `FIPS_ONLY_ENV` minus `FIPS_EXCLUDE`, sharded like `test-fips-shard`.
     It fails when an entry has no issue reference, when an entry matches
     no package (a stale entry excludes nothing), and when nothing is left
     to test. `FIPS_EXCLUDE` holds the packages that fail under
     fips140=only on today's tree, each with its remediation issue. The
     list may only shrink.
   - `ci.yml`: a `fips` job in the code tier (it skips only on a docs-only
     PR) runs `make test-fips-gate` on every push and PR. It is in
     `ci-gate`'s needs with a `code` check line.
   - `nightly.yml`: its header no longer says FIPS is off the push path.
     The nightly job is still the full run with no exclusions.
   - Test: `test/buildgates`' `TestFIPSGateRunsOnPush` checks that ci.yml
     has the `fips` job, that it runs `make test-fips-gate`, that it is
     not schedule- or dispatch-only, and that ci-gate needs it and checks
     it as `code`. It fails on the tree from before this change. The
     existing ci-gate tests cover the tier and needs rules.
   - `docs/SPEC.md` needs no edit: row 14 and the release criteria
     already say the scoped gate runs on push.

## Status

The lane's policy guard blocks edits to `.github/workflows/*.yml` because
`LANE_POLICY_ALLOW` is not set. So the Makefile target and the tests are
on the branch, and the `ci.yml` job and ci-gate lines are in the `wip:`
commit message, ready to apply. `TestFIPSGateRunsOnPush` fails until they
are applied. That failure is the before half of the proof.

- Fixing the excluded packages (#527 / #114 remediation).
