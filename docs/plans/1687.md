# Plan: SPEC row `services` (#1687)

Objective: a service is a signed manifest in go-qrdb with seven lifecycle
verbs (deploy, undeploy, redeploy, start, stop, resume, restart) served on all
six transports and in `sdk/go`; deploy grants a workload identity, a
certificate, a registered name, RBAC from a built-in role and secrets. Then one
`Release` object, A/B slots and one leader-elected rollout controller; then the
go-trusted-platform deployer, boot node and NBD moved in. Design:
`docs/service-plane/architecture.md`. Folds: #1347, #1367.

## Slices, in order

1. **Core model** (`pkg/serviceplane`). `Manifest` (image digest, provenance,
   sandbox/mount/network policy refs, resources, volumes, ports, built-in role,
   registered name, placement) with validation; `Sign` and a `Keyring`
   verifier (Ed25519, ECDSA P-256/P-384); a tenant-scoped `Store` whose
   writes are CAS-arbitrated (`Guard`: `cas.Writer`'s Create and Swap); the
   `Plane` with the seven verbs as a state machine over a `Launcher` and one
   `Grant` per grant kind (all five required; deploy rolls back granted kinds
   on failure, undeploy revokes them). Tests: manifest validation, sign and
   verify (tampered, unknown key, wrong key), store create race and stale
   swap, every verb's legal and refused transitions, grant rollback.
2. **Served.** `ServicePlane` in `pkg/service` over the core, wired in the
   server with go-qrdb's `cas.Writer`; REST, gRPC, QUIC, MCP, Unix and
   embedded; `SDK().Compute().Services()`; permissions `services:*`; CLI
   verbs. Tests: per-transport matrix, authz parity, and
   `make integration-test-services`.
3. **Grants.** Workload identity as a go-xkms x509-svid (#1367),
   `spiffe://<tenant>/svc/<name>`; certificate through the re-exported ACME;
   name in `pkg/registry`; RBAC binding from the manifest's built-in role;
   secrets bound to the identity. Tests per grant and revoke. The RBAC
   grant's binder over go-qrdb IAM is `iam.WorkloadRoleBinder` (the SPIFFE
   ID as an mTLS-only machine principal). Done: a node started with no
   grants builds `grants.All` itself, proven by the services integration
   test granting all five on a real node.
4. **Release and rollout.** One signed `Release` (image, manifest, policy,
   reference values, provenance); A/B slots per service; `Strategy`
   (`Plan`, `Step`, `Rollback`) with `ABSwitch`; one controller elected
   through the scheduler's leader election. Tests: switch, appraisal failure
   rolls back, a second controller never runs. Done: `rollout.PlaneRoller`
   over the plane's slot verbs, run by the node when the runtime supplies an
   appraiser.
5. **Deployer move.** go-trusted-platform `pkg/bootstrap/deployer` to
   `pkg/fleet/deploy` by path-filtered history merge, docker calls repointed
   to `deploy`, no docker default. Its tests move with it.
6. **Boot node and NBD** as broker-class services delivered as a signed
   `Release`; seam rows in go-trusted-platform and go-xkms; the PR marks the
   row shipped in `docs/SPEC.md`.

## Out of scope

- The container runtime rewrite (`container-runtime` row), the OCI registry,
  measured launch and the policy engine (their own rows); this row consumes
  them through the `Launcher` and the policy references.
- Blue/green and canary strategies (later, on the same `Strategy`).
- `FleetDeployService` stays node bootstrap; its verbs are not service verbs.
