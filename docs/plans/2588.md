# Plan: #2588 upgrade aws-sdk-go-v2 to v1.48.0 and smithy-go to v1.28.9

## Objective

Move both modules (the root module and `sdk/go`) to aws-sdk-go-v2 v1.48.0 and
smithy-go v1.28.9, and drop the reason that held them back. Add tests for the
code paths that use the AWS clients, so the new SDK's retry behaviour is
covered.

## Slices

1. The upgrade in `go.mod`, `go.sum`, `sdk/go/go.mod` and `sdk/go/go.sum`
   (b3628e843).
   Test: `go build ./...` in both modules, then
   `go test -race -count=1 -tags codec_json ./pkg/server/`.
2. AWS KMS seal retry and failure-path tests
   (`pkg/server/seal_factory_awskms_retry_test.go`, 893aa5378). They drive the
   real composed KMS client against a fault-injecting httptest endpoint and
   cover the v1.48.0 retry behaviour: transient 5xx, an unmodeled 429 with
   `x-amz-retry-after`, retry exhaustion, terminal errors and a cancelled
   context.
   Test: `go test -count=1 -v -tags 'awskms codec_json' -run 'AWSKMS' ./pkg/server/`.
3. Move `TestInitStandaloneQRDBNode_HardwareStrategyNotCompiled` and
   `TestInitClusteredQRDBNode_HardwareStrategyNotCompiled`, unchanged, into
   `pkg/server/qrdb_node_awskms_absent_test.go` behind `!awskms`. They require
   that awskms is not compiled in, so they made the awskms-tagged package run
   red.
   Test: `go test -race -count=1 -tags 'awskms codec_json' ./pkg/server/` and
   `go test -count=1 -v -tags codec_json -run 'HardwareStrategyNotCompiled' ./pkg/server/`.
