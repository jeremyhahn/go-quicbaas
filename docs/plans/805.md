# Plan: #805 — one package tree for the Software Factory

## Objective

Move `pkg/sdlc` and `pkg/fleet` (formerly `pkg/agent`; ruling 189 / DS-3821
decided that `pkg/fleet` moves too) under `pkg/orchestration`, so the
Software Factory's code is one tree: `pkg/orchestration/{sdlc,fleet,prompts}`.
`pkg/orchestration/prompts` already exists.

## Slices (in order)

1. **Move with history.** `git mv pkg/sdlc pkg/orchestration/sdlc` and
   `git mv pkg/fleet pkg/orchestration/fleet` (with `fleet/deploy`,
   `sdlc/gitsign`, `sdlc/workerimage`). Package names stay `sdlc` and
   `fleet`. Rewrite every import path; fix relative paths inside the moved
   packages that count directory depth (testdata, repo-root lookups).
   No other code change.
2. **References.** Makefile targets and paths, `.github/workflows/ci.yml`
   (race pass and any package lists), scripts, `CLAUDE.md`, the
   `docs/software-factory/` path references and `docs/SPEC.md`.
   `changelog.d/*` fragments stay as history.
3. **Proof.** A guard test in `pkg/orchestration` asserts that `pkg/sdlc`
   and `pkg/fleet` no longer exist and that the moved packages build at
   their new paths (fails before the move, passes after). The unit tests of
   the moved packages and their importers pass.

## Out of scope

- `pkg/signalbridge` stays where it is.
- Any behaviour change, renaming of package identifiers, or content of
  `pkg/orchestration/prompts`.
- `changelog.d/*` history fragments (an internal move: callers of the CLI,
  REST, gRPC and SDK see no change, so no new fragment).
