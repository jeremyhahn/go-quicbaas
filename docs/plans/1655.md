## Slices, in order

1. **Rotation performed (#726, acceptance 3).** A `secrets.rotation` system
   job (`SystemJobIDFloor + 3`, `@every` scan interval, default 5m) in
   `pkg/scheduler/handlers/secrets_rotation.go`, registered in
   `pkg/service/quicbaas.go` once the secrets service and scheduler exist.
   `secretsService.RotateDueSecrets` scans every tenant's secrets as the
   system, and for each with `rotation_enabled=true` and `rotation_next`
   past: stores a new version (same value, encrypted afresh under the
   tenant's context, `rotation_reason=scheduled`) and advances
   `rotation_next`; failures stay due. Each rotation then prunes the secret
   to `rotation_retain_versions` + 1 versions (10 when the policy names
   none), and every Manager write prunes to `secrets.versioning.max_versions`
   (backends implement `VersionPruner`; a prune is compare-and-delete/swap
   on the store, refused without those verbs, and `GetSecret` retries a
   current read a concurrent prune invalidated). The handler runs only as its
   reserved system job: a tenant job naming it is refused. Handler, backend
   and service unit tests; docs in docs/secrets/. **Done.**
2. **#143 tick.** Integration case for `secrets put --from-file` raw bytes
   on every transport. `secrets get` prints the value verbatim, and
   `TestSecretsPutRawFromFile` (test/integration/cli) round-trips a file's
   raw bytes on every transport (CI: needs Docker). **Done.**
3. **Secret-reference resolution and dynamic secrets over go-qrdb's barrier
   and credentials (acceptance 1).** Gated on the go-qrdb/go-xkms pin bump
   (#1389); follows docs/plans/1889.md. Until then, record the hold.
   **Done on the current pin:** dynamic secrets are minted into go-qrdb's
   barrier-backed credential store (`credential` generator,
   `pkg/credentials/credstore`, in the caller's tenant) and resolve as
   `credential://dynamic-<id>` references through the server's secret
   registry; revoke and expiry (a lease-manager expire hook) delete them, and
   the dynamic-secrets records never carry the value. Tests: credstore,
   lease expire hook, service material, server tenant routing. The SDK
   delegated resolver in docs/plans/1889.md stays held on the pin bump.
4. **Storage-level write arbitration across nodes (acceptance 4).** Already
   built: KV backend pointer writes are guarded (`PutIfAbsent`,
   `CompareAndSwap`, `CompareAndDelete`) and the server store forwards them
   to go-qrdb. Added `TestKVBackend_TwoNodesArbitrateConcurrentWrites` (two
   backends, one arbitrating store, racing writers) and the cross-node
   paragraph in docs/secrets/architecture.md. **Done.**
5. **Acceptance 2.** docs/secrets/architecture.md "Two implementations"
   names the parallel backend and its DEKs and bounds it (stays until the
   owner's word; new capabilities go to go-qrdb). **Done.**
6. **Codex findings (verify refusal).** Backends gained
   `StoreVersionIfCurrent` (KV: pointer CAS; memory; Manager). Rotation
   writes via it with the read `version` (update/disable/delete interleaving
   test); an enabled policy without a deadline gets one interval out, and a
   zero deadline is due (MCP-shaped test); plain `secrets get` prints a raw
   value verbatim when `--output` is unset (command test); the two-node test
   gives each node its own write locks so the store's guards contend; a
   recreation at the read version is refused on every backend
   (`conditional_write_test.go`); the scan skips disabled, counts unreadable.
   Verify 2: conditional writes refuse a store without CAS; encrypted keeps
   the record's key and algorithm; `get` (default and `--output raw`) prints
   every value verbatim, a JSON-object file too (REST get has no metadata). **Done.**
7. Mark the row shipped in docs/SPEC.md: not in PR #2445. It waits for
   slice 3 (acceptance 1), held on the go-qrdb/go-xkms pin bump (#1389);
   docs/SPEC.md keeps the row `in progress` until then.
