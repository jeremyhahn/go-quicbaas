## Slices, in order

1. **Rotation performed (#726, acceptance 3).** A `secrets.rotation` system
   job (`SystemJobIDFloor + 3`, `@every` scan interval, default 5m) in
   `pkg/scheduler/handlers/secrets_rotation.go`, registered in
   `pkg/service/quicbaas.go` once the secrets service and scheduler exist.
   `secretsService.RotateDueSecrets` scans every tenant's secrets as the
   system, and for each with `rotation_enabled=true` and `rotation_next`
   past: stores a new version (the same value re-encrypted under a fresh
   DEK; the version records `rotation_reason=scheduled`), advances
   `rotation_next` by the interval, and destroys versions beyond
   `rotation_retain_versions`. Failures stay due for the next scan.
   Tests: handler unit test (job definition, result message, scan error);
   service test (due secret rotated and advanced, not-due and disabled
   untouched, retention prunes); `make integration-test-secrets`.
   Docs: docs/secrets/ say what a performed rotation does.
2. **#143 tick.** Integration case for `secrets put --from-file` raw bytes
   on every transport, if absent.
3. **Secret-reference resolution and dynamic secrets over go-qrdb's barrier
   and credentials (acceptance 1).** Gated on the go-qrdb/go-xkms pin bump
   (#1389); follows docs/plans/1889.md. Until then, record the hold.
4. **Storage-level write arbitration across nodes (acceptance 4).** Version
   writes compare-and-set on the KV backend (`kv_backend_cas_test.go` is
   the start); a two-node test that concurrent writers get distinct versions
   and the loser retries or fails cleanly.
5. **Acceptance 2.** QuicBaaS's own backend and DEKs stay until the owner's
   word; the row records that the parallel implementation is named and
   bounded (docs/secrets/architecture.md), and its removal is not this row.
6. Mark the row shipped in docs/SPEC.md.

## Out of scope

- The go-qrdb / go-xkms pin bump and the #1814 embedded identity work.
- Removing the parallel backend without the owner's word.
- Generating new secret values server-side (a rotation keeps the value;
  a value generator is a later policy option).
