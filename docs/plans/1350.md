# Plan: #1350 service-policy, policy as signed data, one Go engine

## Objective

The Go-coded policies move into one `pkg/policy` engine that dispatches on the
policy kind through a map. Policy documents are data: they are signed with the
tenant key through go-xkms, stored in go-qrdb, and verified on load. IAM
authorization stays with go-qrdb's PDP (docs/service-plane/architecture.md,
"Service policy"; SPEC row `service-policy`).

## Start condition (ruling 109 waiver)

The waiver holds only while the move touches no measured-launch path. The
trust-tier policy (`pkg/orchestration/trust_policy.go`,
`TrustLevel.RequiresMeasuredLaunch`, used by `container_attestation.go`) is on
that path, and `measured-launch` is still `planned`. So the trust-tier kind is
out of every slice below until measured launch lands or a ruling moves it in.
No slice edits `trust_policy.go`, `container_attestation.go` or
`container_trust.go`.

## Slices, in order

1. **Engine core and the sandbox kind** (this slice).
   - `pkg/policy`: `Kind`, `Document`, `SignedDocument`, the `Signer` and
     `Verifier` seam, `Evaluator`, and `Engine` with map dispatch. `Load`
     verifies the signature and validates the spec before a document is used;
     an unsigned, tampered or unknown-kind document is refused.
   - `pkg/policy/sandbox`: `pkg/fleet/sandbox_policy.go` moved with `git mv`
     (history kept) as `sandbox.Resolver`, plus the `sandbox` kind evaluator
     over `orchestration.ResolveSandboxMode`. `pkg/fleet` uses it; the old file
     is gone once the fleet is wired.
   - Tests: engine dispatch, duplicate registration, verify-on-load refusals
     (unsigned, bad signature, wrong tenant, unknown kind, bad spec); the
     moved resolver test; the sandbox kind's allow and deny decisions.
2. **go-xkms signer**: an adapter from the re-exported go-xkms client
   (`sdk/go/xkms` Sign/Verify) to `policy.Signer`/`policy.Verifier`, signing
   with the tenant key. Contract test against the embedded go-xkms.
3. **qrdb store**: signed documents kept in the tenant's qrdb store; reads
   verify on load. Tests over the in-memory and embedded stores.
4. **Remaining kinds, one per slice**: mount, sandbox-network, communication,
   role, lifecycle, spend, admission. Each moves its source and tests from
   `pkg/orchestration` with `git mv` into `pkg/policy/<kind>`, registers its
   kind, and removes the copy left behind only after callers are wired.
5. **Verbs on every transport**: put, get, list and evaluate policy documents
   on REST, gRPC, QUIC, MCP, Unix and embedded, reachable through `sdk/go`,
   with `make integration-test-policy`.
6. **gtp rego mapping**: go-trusted-platform's rego rules mapped onto the
   kinds (a table in the design page plus a test per mapped rule).

## Out of scope

- The trust-tier kind (see the start condition).
- IAM authorization: it stays go-qrdb's PDP; no kind duplicates it.
- Rewriting any evaluator: each is moved, not rewritten.
