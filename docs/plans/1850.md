# Plan: #1850 — a CI job runs the tenantbarrier integration suite

## Objective

`test/integration/tenantbarrier` needs the seal-enabled harness
(`make integration-test-tenantbarrier`, `docker-compose.seal.yml`), so the
base run (`docker-compose.integration.yml`) drops it through
`SEAL_LANE_PKGS_RE`. No workflow calls the seal-enabled target, so the suite
is dark: a regression in the Shamir, passphrase or none tenant-barrier
lifecycle turns no gate red. After this change a CI job runs it.

## Slices

1. **Workflow job.** `.github/workflows/integration.yml` gains an
   `integration-test-tenantbarrier` job beside `integration-test`: same
   runner selection, full-tier `if:`, checkout, Go setup and disk handling.
   It runs `make integration-test-tenantbarrier` with its output teed into
   `tenantbarrier-test.log` (`set -o pipefail`, so a failing suite fails the
   step), and uploads `*.log` as the `tenantbarrier-test-results` artifact on
   every outcome. Teardown is the Makefile target's own EXIT trap
   (`down --volumes --remove-orphans --rmi local`), as for the base suite.
   The suite runs `go test -v`, so the job log carries each test's result.
2. **Compose comment.** `docker-compose.integration.yml` says, beside the
   base-run command, that the seal-lane packages it excludes run in that
   job, so the exclusion cannot again hide a suite.

Tests: the proof is CI itself. The PR's `ci:full` run shows the job and its
per-test results; a throwaway commit that makes one tenantbarrier test fail
turns the job red, and is dropped before landing (issue Verification).

## Status: blocked on the protected path

Lane aq1850's policy guard refuses every edit to
`.github/workflows/integration.yml` (a protected path; a lane may change it
only when its run sets `LANE_POLICY_ALLOW`). Slice 2 waits for slice 1 so the
compose comment never names a job that does not exist. The job slice 1 adds,
after the base job's upload step:

```yaml
  integration-test-tenantbarrier:
    name: Tenant Barrier Integration Tests
    runs-on: <the integration-test job's runs-on expression, verbatim>
    if: github.event_name == 'push' || github.event_name == 'workflow_dispatch' || contains(github.event.pull_request.labels.*.name, 'ci:full')
    timeout-minutes: 60
    steps:
      - <Free up disk space, Checkout code, Set up Go, Download
         dependencies: verbatim from the integration-test job>
      - name: Run tenant barrier integration tests
        timeout-minutes: 45
        shell: bash
        run: |
          set -o pipefail
          make integration-test-tenantbarrier 2>&1 | tee tenantbarrier-test.log
      - name: Upload tenant barrier test results
        if: always()
        uses: actions/upload-artifact@v6
        with:
          name: tenantbarrier-test-results
          path: |
            *.log
          retention-days: 7
```

## Out of scope

- `ci.yml` is ci-template-owned (v1.34.1); its integration stage is
  unchanged. `nightly.yml` and `batch.yml` are unchanged: integration.yml
  runs on every main push touching code and on `ci:full` PRs.
- Failures the first run exposes in code that ran dark are reported, and
  fixed here or by the coordinator in a separate issue; no test is skipped.
- Docker is not available in the lane, so the target cannot run here.
