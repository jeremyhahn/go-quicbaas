# Plan: #527 pkg/sdlc under fips140=only (sub-112-bit webhook HMAC keys)

## Objective

`pkg/sdlc` passes `GOFIPS140=latest GODEBUG=fips140=only go test ./pkg/sdlc/...`
(measured red on 2026-11-13: `crypto/hmac` panics in
`TestVerifyWebhook_AcceptsOnlyAGenuineSignature` on the 6-byte fixture key),
and a deployment configured with a short webhook secret gets a typed error,
not a panic.

## Re-measured scope (2026-11-13)

- `FIPS_EXCLUDE` and the per-package FIPS baseline no longer exist in
  `ci.yml`: the FIPS job moved to `nightly.yml` and runs the whole root module
  (`make test-fips-shard`) with no exclusion list. Issue scope item 3 has
  nothing left to edit.
- Short fixture keys: `[]byte("s3cret")` / `[]byte("other")` in
  `forge_gitea_test.go`, `forge_gitea_onboarding_test.go`,
  `forge_github_webhook_test.go`, `webhook_test.go`; `"hmac"` in
  `onboarding_test.go`; `"shhh"` in `triage_scheduler_test.go`; `"secret"` in
  `pkg/service/sdlc_service_test.go`.

## Slice (one)

1. Runtime decision: `MinWebhookSecretBytes = 14`. `checkWebhookSecret`
   refuses an empty or short secret at configuration time, in onboarding
   (`ensureWebhook`, before a hook is created) and in webhook ingest, with
   the typed `WebhookSecretTooShortError` (matches `ErrWebhookSecretTooShort`
   and `ErrWebhookSecretMissing`, so HTTP answers 401). The Gitea and GitHub
   `VerifyWebhook` refuse a short key as `ErrWebhookUnverified` before
   `hmac.New`, so no caller can reach the panic.
2. Fixture keys lengthened to >= 14 bytes.

Tests added: errors table rows for the new type; ingest refusal
"secret under 112 bits"; `TestOnboard_RefusesAShortWebhookSecret`; Gitea and
GitHub fail-closed cases for a short key with a precomputed signature (they
were accepted before the change).

## Out of scope

- GitLab compares a token, not an HMAC; it gets the floor only through the
  shared ingest/onboarding check.
- Other packages' FIPS failures (nightly job).
