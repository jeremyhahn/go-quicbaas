# Plan: SPEC row container-runtime (#1682)

## Objective

One container runtime, `internal/containerruntime`: runc `libcontainer`,
`go.podman.io/image` and `go.podman.io/storage` in-process, in the fleet node
agent only, internal to this module (no public package, SDK, CLI flag or
config value), co-located with quicbaasd. `ExecContainerRuntime` and the
docker/podman selector go once the agent runs jobs through it. Folds: #902
phase 5 and #1352. Design: `docs/service-plane/architecture.md`.

## Slices, in order

1. **In-process runtime (item 1).** Already built: libcontainer engine, image
   pull and layer unpack through go.podman.io. This slice adds
   `TestPackageNeverDialsARuntimeDaemon` (no `net`, no Docker, containerd,
   Podman, CRI or systemd-bus client) beside `TestPackageNeverImportsOSExec`,
   and moves the SPEC row to `in progress`.
2. **Contract tests (item 2).** Port the named this-repo contract tests
   (`TestExecContainerRuntime_*Validation`, `_VerifyPinnedImage`,
   `_Exec_*`, `_RunInteractive_*`, `TestSweepOwned_*`, `TestInspectImage_*`,
   `TestRunImage_*`, `TestContainerSpec_Validation`,
   `TestContainerMount_Validate`) to run against `internal/containerruntime`
   through an `orchestration.ContainerRuntime` adapter.
   - 2a (done): `JobRuntime` serves Run, Exec, Stop, Remove, Logs,
     IsRunning, IsAvailable and Pull in-process; exec gains stdin and
     context cancellation (SIGKILL). `TestJobRuntime_*` covers the
     validation, pinned-image, Exec and lifecycle contracts.
   - 2b (done): RunInteractive through `Runtime.StartAttached` (init with
     stdin/stdout pipes rather than log files), bound to its context and
     removed on exit, as `run -i --rm` was.
   - 2c (done): `JobRuntime` serves `SweepOwned`, `InspectImage` and
     `RunImage`. Containers take the image's entrypoint, command,
     environment, working directory, user and labels as `docker run` does,
     and ulimits map onto the init process's rlimits. A stop of a process
     that has already exited waits for its exit record instead of failing.
     `TestRunImage_CompletedRunIsNotRemovedAgain` and
     `TestRunImage_FailedRemovalKeepsTheRunsError` run as
     `TestJobRuntime_RunImage` subtests.
   - 2d (done): restart orphans. Every bundle keeps a `container.json`
     record (id, name, image, created_at, labels). `Runtime.ListLeftovers`
     names the bundles that no one in this process registered.
     `Runtime.ReclaimLeftover` kills and destroys one through the engine
     (libcontainer `Load`, SIGKILL, poll to `Stopped`, `Destroy`) and
     removes its rootfs and bundle; every step is idempotent.
     `JobRuntime.SweepOwned` reclaims the owner's leftovers after its own
     containers. A record it cannot read is a `ContainerSweepError` that
     names no container, which ports
     `TestSweepOwned_ReportsAnEnumerationItCouldNotMake`.
     `TestReclaimLeftover_ContainerOfAKilledOwner` (integration) kills the
     process that started a running or an exited container and reclaims it
     from a fresh runtime on the same root.
   - Gap: `NetworkMode` and `Ports` are not wired. Every container gets its
     own network namespace; a job asking for any network but "none", or for
     published ports, is refused with `ErrNetworkUnsupported` before its
     container is created.
   - 2e (done): fixes kept from a later lane. A job's ulimits reach
     libcontainer's rlimits (specconv leaves them unset). A
     `name:tag@digest` reference is pulled by its digest. A container
     removal continues past a missing layer to delete the container
     record. With a registry, the worker image refresh pushes the
     candidate under `<tag>-candidate` and smokes that push's
     digest-pinned reference, so an agent with its own image store
     pulls the exact build; with none it smokes the built image ID. The
     release tag moves only after the gate.
3. **Agent job wiring (items 2, 3).** Registered in the agent, not
   selectable; selection is slice 3b. `quicbaas fleet serve` registers the
   in-process runtime (through `internal/inprocessruntime`, from the
   agent's `main`), with its state under `<work-dir>/containers`. No
   `--container-runtime` value selects it: `Config.Validate` and both
   exported resolvers refuse "libcontainer", and `auto` never takes it (it
   probes Docker, then Podman), because the in-process runtime has no
   container networking and no seccomp or AppArmor confinement yet. Fleet
   jobs still run on docker or podman.
   `TestDaemonNeverLinksContainerRuntime` stays green, and
   `TestFIPSModuleUnaffectedByTheRuntime` checks `fips140.Enabled()` in a
   cgo binary that links the runtime. quicbaasd's embedded node builds no
   container runtime (slice 5). The runtime lives under `internal/` and
   pkg/fleet exports no hook for it.
   - 3b (open, #2665): the in-process runtime becomes the agent's runtime.
     It stays internal: there is no `libcontainer` value for
     `container_runtime` or `--container-runtime`. It takes over when slice
     4 removes the docker/podman selector, once the gaps below are closed.
     Seccomp is done: every unprivileged container carries Docker's
     default profile, resolved for its final capability set; privileged
     containers get none; a build without the `seccomp` tag refuses such
     containers with `ErrSeccompUnsupported`. Still open before selection:
     networking beyond "none" and published ports (today `JobRuntime`
     refuses them with `ErrNetworkUnsupported`), AppArmor, building the
     agent with libseccomp and the `seccomp` tag, the worker-image refresh
     reaching the agent's image store, and the selector. Slice 4 waits on
     it.
4. **Removal (item 2).** Delete `ExecContainerRuntime`
   (`pkg/orchestration/container_runtime*.go`, `container_exec.go`,
   `container_sweep.go`, `container_reaper.go`, the shell-outs in
   `container_image.go`) and the selector in `pkg/fleet/container_runtime.go`,
   with `--container-runtime` docs.
5. **Co-location (item 4).** Single-node deploy starts a local agent enrolled
   against `https://localhost:<rest-port>`; a work-dir lock test proves two
   runtimes never share a work dir.
   - Already on main: `fleet deploy --local` (no ssh); `make build-agent`
     and `build-agent-fips` (cgo, the `--binary` default); the work-dir
     lock (`fleet.AcquireWorkDirLock`, tested in
     `cmd/quicbaas/fleet_serve_workdir_lock_test.go`); the dev cluster's
     gRPC ports moved to 9290+, clear of the agent's 9091.
   - Done: the embedded fleet node builds no container runtime. Under a
     sandbox policy it keeps only ollama and runs opt-in; with no backend
     left it does not start (`embedded_fleet_node_no_runtime_test.go`).
   - Done: the orchestration service hands its backends no container
     engine, and neither sweeps nor reaps containers of its own
     (`lifecycle_orchestration_no_runtime_test.go`). A sandboxed spawn goes
     fleet-first to the co-located agent; one left on a local backend fails
     closed under Required (`resolveSandboxMode` sees no runtime).
   - Done: the co-located agent sweeps, once at startup, the owners an
     earlier quicbaasd ran containers under, listed exactly in its
     `legacy_container_owners` (`"orchestrator:<abs storage.data_dir>"` and
     the embedded node's `data_dir`). Best effort: a failure is logged and
     the agent starts. quicbaasd itself still runs no container work
     (`runtime_legacy_sweep_test.go`).
   - Left: the worker image refresh (`lifecycle_sdlc_worker_image.go`)
     still builds, tags and pushes through an `ExecContainerRuntime`, built
     only when `sdlc.worker_image.enabled`. `JobRuntime.TagImage` is done
     in-process (storage `AddNames`, by reference or `sha256:` ID).
     `JobRuntime.PushImage` is done in-process (go.podman.io/image copy
     from containers-storage to `docker://`, returning the pushed digest;
     round trip against an in-memory registry in `backends_linux_test.go`).
     The Dockerfile reader is done (`dockerfile.go`: continuations,
     comments, heredocs, JSON forms, ARG/ENV expansion; the worker
     Dockerfile parses whole). The build planner is done
     (`dockerfile_plan.go`: each stage's base configuration, ARG and ENV
     scope, user, working directory, shell, entrypoint, command and labels;
     RUN and COPY steps with their environment and paths resolved; the
     worker Dockerfile plans whole). Committing a build container's layer
     as an image is done (`backends_commit_linux.go`: one uncompressed
     layer on the base image with the step's configuration and history,
     written through the containers-storage destination, so it inspects,
     runs, tags and pushes like a pulled image; the store round trips need
     root and run in `make integration-test-containerruntime`). Next: run
     the planned stages, then a Dockerfile build with an empty context
     (FROM, ARG, ENV, RUN, USER, WORKDIR, LABEL, ENTRYPOINT, CMD; RUN steps
     in libcontainer, each committed as a layer), served by the co-located
     agent. After that, slice 4.
6. **#902 phase 5.** Ephemeral storage tiers on the runtime; secrets and keys
   through KMS and Credentials, with tests.
7. **Ship.** SPEC row `shipped`, ROADMAP agrees, PR closes #1682.

## Out of scope

- Item 5, the go-trusted-platform seam: the runtime is internal to this
  module, so that repo cannot import it. How it drops its copy is decided in
  its own seam row; this row records it.
- The services, oci-registry, measured-launch and service-policy rows.
- Integration tests that need Docker (`make integration-test-containerruntime`)
  run in CI, not in a lane.
