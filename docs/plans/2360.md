# 2360: while the base branch is red, adopt only main-fix issues

## Objective

IssueSource.Poll adopts every ready issue whatever the state of the base
branch's CI, so new feature work starts on a broken base. While the head of
the project's default branch has a failed check, adopt only issues labelled
`main-fix`. A pending head, or a head with no checks, is not red: an unknown
base must not stop all work.

## Slices

1. Base admission (this slice).
   - pkg/sdlc/base_admission.go: `DefaultMainFixLabel`, `BaseState` (`Red`
     only for CIFailure), `readBaseState` (GetBranch, ListCheckRuns,
     ciStateOf; a blank branch reads `main`), `admitOnBase`.
   - IssueSource.Poll reads the base once per sweep (a read error is
     unavailable, like the other sweep reads) and skips every adoptable issue
     that `admitOnBase` refuses. parkedSpecs is unchanged.
   - Tests: TestAdmitOnBase_* and TestReadBaseState_* in
     base_admission_test.go; TestIssueSource_RedBaseAdoptsOnlyMainFix,
     TestIssueSource_RedBaseTurnedGreenAdoptsTheRest,
     TestIssueSource_PendingBaseAdoptsEverything in issue_source_test.go.

A skipped issue is safe: adoption is create-if-absent and a spec missing from
a sweep cancels nothing, so the issue is adopted on a later sweep once the
base is green.

## Out of scope

- A per-project or per-binding main-fix label (the constant is the default).
- Parking or cancelling work already adopted when the base turns red.
- Changing parked specs: a parked issue is adopted blocked and starts nothing.
