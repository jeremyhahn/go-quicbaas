# Plan: branch hygiene sweep (#2366)

## Objective

Delete, under a lease, the factory branches (lane and checkpoint branches)
that main or an open pull request head already carries, so that the factory
branches left equal the open pull requests plus the live lanes. Report a
stranded-branch count on each pass.

## Slices, in order

1. Branch inventory and a pure sweep (this slice).
   - `ForgeBranchInventory` (ListBranches, BranchContained): an optional
     interface that adapters may implement. It is kept off `ForgeBackend`, so
     existing fakes and adapters do not break.
   - GitHub implementation: a paged `/branches` listing and a `/compare`
     status check.
   - `SweepBranches`: looks only at the `issue/`, `feature/` and `hotfix/`
     prefixes. It keeps open pull request heads and live lanes. It deletes
     carried branches under a lease (re-read the SHA before deleting), and
     counts the rest as stranded.
   - Tests: branch_hygiene_test.go (carried by main, carried by a PR head,
     PR head kept, live lane kept, stranded counted, lease keeps a moved
     branch, other prefixes ignored, a delete failure is recorded,
     a listing error fails the whole sweep, a forge without the inventory is
     refused, end state is PRs plus lanes) and forge_github_branches_test.go
     (paging, compare statuses, empty input refused).
2. Wire the sweep into a factory pass that supplies the open pull requests
   and the live lanes, and reports StrandedCount.
3. Gitea and GitLab inventory implementations.
4. A transcript retention check before deleting a lane branch.

## Out of scope for slice 1

- Changes to the per-merge delete (`deleteMergedSource`) and to the merge
  train's own `queue/` cleanup.
- A stranded-work check before a per-merge delete (another issue).
