# Plan: #1534 TypeScript SDK QUIC transport (WebTransport over HTTP/3)

## Objective

`QuicClient` in `sdk/typescript/src/quic.ts` connects to the quicbaas server
over WebTransport over HTTP/3 (draft-ietf-webtrans-http3, pinned at -16;
owner ruling relayed as CA m624 item 1) and serves every verb of the
`sdk/typescript/src/interfaces.ts` client families, `ceremony.claimShare`
included. Until then the typed `QuicNotImplementedError` /
`TransportNotSupportedError` refusals stand unchanged.

## Slices, in order

1. **Standards first (this slice).** `docs/reference/draft-ietf-webtrans-http3-16.txt`
   and its index row in `docs/reference/README.md`. ROADMAP Dependencies
   gets the standards-watch line, which is a protected path for lanes and
   is left to the coordinator:
   `- Standards watch: draft-ietf-webtrans-http3 (WebTransport over HTTP/3), pinned at revision -16, for the server endpoint and the sdk/typescript QUIC client (#1534) ([copy and index](docs/reference/README.md))`
2. **Provider seam (go-qrdb#1243).** The server's HTTP/3 listener is the
   embedded go-qrdb unified server. It must send the draft -16 section 3
   settings (SETTINGS_WT_ENABLED, SETTINGS_ENABLE_CONNECT_PROTOCOL,
   SETTINGS_H3_DATAGRAM, max_datagram_frame_size > 0, reset_stream_at) and
   hand authenticated sessions to a module handler through an sdk/go
   option. Checked 2026-11-13: go-qrdb v0.58.2-alpha (the newest release)
   has none of it and does not depend on webtransport-go. Then: pin bump.
3. **Request framing (CA ruling needed).** `sdk/go/transport/quic` is REST
   over HTTP/3 with no frame protocol of its own, so how a request rides a
   WebTransport bidirectional stream is unruled. Candidate: RFC 9292 Binary
   HTTP, one request per stream, which needs its own docs/reference copy.
4. **Server endpoint.** WebTransport session handler in the server that
   dispatches each stream's request into the same REST handlers and auth
   chain the Go QUIC transport reaches. Go unit tests for settings,
   session accept and dispatch.
5. **TS client connect/disconnect.** `QuicClient.connect` opens a
   `WebTransport` session to `config.quic.endpoint`; `disconnect` closes it.
   Vitest: connect, disconnect, connect failure mapped to typed errors
   (a fake `WebTransport` injected through the config).
6. **TS verbs.** Each family (barrier, ceremony incl. claimShare,
   bootstrap, projects, sdlc, accounts, rest of #812) over the session.
   Vitest per verb: framing and error mapping.
7. **Integration + claims.** `test/integration/` (docker): the TS client
   serves each family over WebTransport, a claimShare round trip for an
   enrolled officer and the refusal for a non-officer. The claims audit
   lists QUIC as a served TS transport. changelog.d entry.

## Out of scope

- Go transports (#1501).
- A framing of our own (ruled out by standards first, CA m586).
- Any change to the typed refusals before slice 5 lands.
