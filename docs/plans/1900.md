# Plan: #1900 a bound bearer's identity subject names the account username

## Objective

`auth.SubjectFromIdentity` names a caller that go-qrdb's `BindUser` has bound
by the account's username (`Identity.AccountName()`) and account id
(`Identity.UserID`), never by the decimal account id `BindUser` leaves in
`Subject`. `MarkTokenSubject` with a verified uid also sets `Identity.UserID`
(and `Username` for a username sub), so qrdb resolves the caller by id.

## Prerequisite (blocker)

The change needs go-qrdb sdk v0.51.0-alpha (`Identity.UserID`, `Username`,
`AccountName`, `BindUser`). main pins v0.30.1-alpha; the re-pin is #1816,
carried by PR #1845 (#1818). This row lands after #1845 merges: on main as it
is, `pkg/auth` does not build with the change.

## Slices

1. `pkg/auth/identity_subject.go`: port the change preserved at the #1845
   head 15e3690af (MarkTokenSubject sets UserID/Username; SubjectFromIdentity
   projects through AccountName and UserID; `boundByQRDB` keeps an unbound
   token's sub). Tests in `identity_subject_test.go`, on identities made by
   `BindUser` itself:
   - success: `TestSubjectFromIdentity_BoundAccount`,
     `TestSubjectFromIdentity_BoundBearer`, `TestMarkTokenSubject_BindsAccount`;
   - refusal: `TestMarkTokenSubject_NoUIDBindsNoAccount`.
2. `pkg/api/rest/principal_test.go`: a bound bearer reads its own sessions by
   username (allowed) and another user's (403).
3. `pkg/service/ssh_service_audit_test.go`: the SSH sign audit names a bound
   bearer by username and account id.

## Verification

`make` unit targets for pkg/auth, pkg/api/rest, pkg/service with the CI tags;
the integration target of the IAM feature.

## Out of scope

The go-qrdb pin bump itself (#1816 / #1845) and any other #1845 cut row.
