# Plan: #549 rag/watcher `Config.DebounceDelay` configures nothing

## Objective

`watcher.Config.DebounceDelay` is validated and documented but never read;
the only coalescing window is `BatchInterval`. Ruling 189 (DS-3821): remove
the field unless the SPEC row names debounce. The `rag` row in
`docs/SPEC.md` does not name debounce, so the field is removed.

## Slices

1. Remove the knob (one commit):
   - `pkg/rag/watcher/debouncer.go`: drop the `delay` field and the
     `newDebouncer` parameter; document that the debouncer coalesces per
     path until the next `BatchInterval` flush.
   - `pkg/rag/watcher/config.go`: drop `DebounceDelay`, its default and
     its `Validate` check; document `BatchInterval` as the one window.
   - `pkg/rag/watcher/errors.go`: drop `ErrInvalidDebounceDelay`.
   - `pkg/rag/watcher/watcher.go`, `pkg/rag/indexing/service.go`: stop
     passing / setting it.
   - Tests: drop every `DebounceDelay` setting and the negative-delay
     validation cases; add `TestConfig_NoDebounceDelayField`, which fails
     on the old `Config` (the field exists) and passes after.
   - `changelog.d/549-watcher-debounce-delay-removed.md`: callers see a
     removed field and sentinel.

## Out of scope

- `BatchInterval: 0` is documented as "disables batching" but
  `time.NewTicker(0)` panics in `processBatches`; reported, not fixed here.
