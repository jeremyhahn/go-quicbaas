# Plan: #827 — AuditLogger.Emit returns error; propagate it

## Objective

go-qrdb's `AuditLogger.Emit` returns an error (`*sdk.NodeAuditWriteError`
when the event missed its durability boundary). Ruling 189 (DS-3821):
propagate it and fail closed. `pkg/server/node_audit_logger.go` discarded it
with `_ =` in `Log` and `LogAsync`.

## Slice 1 (this lane)

- `NodeAuditLogger.Log` returns the sink's `Emit` error, wrapped so
  `errors.As(err, *sdk.NodeAuditWriteError)` still finds it. Callers of
  `iam.AuditLogger.Log` already handle its error.
- `NodeAuditLogger.LogAsync` has no error return (the `iam.AuditLogger`
  contract): it logs the failure with `slog.Warn` instead of discarding it.
- Tests (`pkg/server/node_audit_logger_test.go`), with a failing sink double
  whose `Emit` returns `*sdk.NodeAuditWriteError`:
  - `Log` returns the write error (fails before: Log returned nil);
  - `LogAsync` with the failing sink does not panic and reports the failure.
- `changelog.d/827-audit-log-fails-closed.md`: callers see the new error.
- `docs/SPEC.md` is a protected path for this lane (policy guard); its
  audit-logging row note is left to the coordinator.

## Out of scope

- Changing the `iam.AuditLogger` interface (`LogAsync` stays void).
- go-qrdb's middleware `audit_failure_policy` (go-qrdb owns it).
- No fan-out sink exists in this repository; none is added.
