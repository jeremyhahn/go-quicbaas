# Plan: #2654 the sealed-daemon ceremony test trusts the daemon's CA chain

## Objective

`TestCeremonyE2E_SealedDaemonServesTheCeremonyOverCLI`
(`test/integration/init/ceremony_e2e_test.go`) called the sealed daemon over
TLS without trusting the daemon's own CA chain, so the handshake failed and
the Integration job on main went red. The CLI must trust the chain the daemon
writes under its data dir (`caChainPath(dataDir)`); TLS is never turned off.

## Slices

1. Pass `--tls-ca caChainPath(dataDir)` to every CLI verb the test runs
   against the sealed daemon (`init status`, `init officer register`).
   Test: `make integration-test-init` runs the ceremony test green.
2. PR #2660 follow-up: reproduce the red `Lint` and `Integration` checks on
   the PR head with their Makefile targets (`make lint`,
   `make integration-test-init`) and fix what they name in the files this PR
   changes.

## Out of scope

- Changing the daemon's TLS defaults or the CLI's trust store lookup.
- Other integration tests that do not use the sealed-daemon ceremony.
