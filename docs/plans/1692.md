# Plan: SPEC row mcp-server (#1692)

## Objective

The Model Context Protocol surface is scope-filtered per principal, and an
unauthenticated `tools/list` does not return the full registry (docs/SPEC.md
row `mcp-server`, detail in `docs/mcp-server/`). Every folded item below is
done with a test that fails before and passes after; the row's PR #2457
marks the row shipped in docs/SPEC.md.

## Slices, in order

1. Folds already open: merge PR #2388 (`fold/config-docs-tests`); account
   for the fold refs (1629c is carried by the PR #2248 merge; the #1821 plan
   merges as-is). Tests: the touched packages' unit tests stay green.
2. #1130: `tools/list` with no identity returns only the public tools; the
   public `quicbaas_readiness` is served, not refused. Test: an anonymous
   MCP session lists no gated tool and reads readiness.
3. #1857 and #1821: health, version, liveness, readiness, qrdb_health and
   the federation/login tools are public on the composed MCP server, as on
   gRPC and REST (needs the go-qrdb public-tool seam; see
   docs/plans/1821.md). Test: each is callable anonymously on the composed
   server; a gated tool is still refused.
4. Scope filtering per principal: `tools/list` lists only the tools the
   caller's permissions allow. Test: two principals, two lists.
5. #1631: the xkms CA (7) and PIN (8) tools serve through a shared
   `pkg/api/xkmsca` servicer adapter (fold refs `row/1631-shared-xkms-ca-adapter`,
   `-b` and `lane-wip/aq1631/...`; merge one, drop the duplicates). Test: each
   CA tool returns what REST returns, not OperationNotSupported.
6. #1633 remainder: session tools stay self-service with no token hashes
   (landed via #2248); check owner and tenant scope. Test: another
   principal's session is refused.
7. #1644: orchestrator tools carry the start_job, spawn and get_job_status
   fields the SDK sends and reads; Health reports one timestamp unit. Test:
   an SDK-shaped round trip over MCP.
8. #2228: `mcp.bind_address` binds the MCP listener. Test: the config value
   reaches the listener address.
9. #1926: an integration test drives the real combined MCP server through
   the go-qrdb sdk/go constructor seam (`make integration-test-mcp`).
10. Close: tick the acceptance in docs/SPEC.md (row shipped).

## Status (2026-11-14)

- Slice 1 done: PR #2388 merged (docs/SPEC.md and ROADMAP.md held on the
  row's side by the lane policy guard), and every fold ref accounted for
  (1629c dropped, #1821 plan merged, #1631 adapter merged as
  `pkg/api/xkmsca`, the aq1631 WIP dropped). 2026-11-15: #2388's newer
  head (bde4fe65d) merged the same way; its SPEC C1 and roadmap
  object-storage hunks are held for the coordinator.
- Slices 2-4 are blocked on the go-qrdb pin (v0.30.1-alpha). Its composed
  MCP server builds mcp-go with no hooks (`GetHooks()` is nil), takes no
  `WithToolFilter` and has no HTTP middleware option, so quicbaas cannot
  filter `tools/list` or let an anonymous caller through to the public
  tools. Today an anonymous caller gets `401` on `initialize`, so it is not
  shown the registry, but public readiness is refused too. Needs the #1389
  pin bump to a go-qrdb with a tool-filter (or hooks) seam and a public-tool
  lister.
- #2228 done: `ServerConfig.NodeListenHost` makes an enabled protocol's
  bind_address the node host (go-qrdb binds every listener on one host);
  validation refuses disagreeing overrides.
- #1644 done: start_job binds the caller's tenant and carries the SDK's
  fields; spawn carries env/sandboxed and returns container_id,
  resolved_agent_id and failovers; get_job_status returns prompt_append.
  The SDK MCP transport decodes SpawnSession, StartJob, GetJobStatus and
  Health (the MCP wire keeps RFC 3339 timestamps; the SDK converts them to
  nanoseconds); gRPC StartJob/Health report nanoseconds.
- #1631 done: the 7 xkms.ca.* tools serve through `xkmsca.Servicer`
  (wired in lifecycle_mcp); no CA wired = service-unavailable. The 8 PIN
  tools stay unsupported, matching REST's unimplemented PIN routes.
- #1633 done: session touch resolves the session through `callerSession`
  before UpdateActivity, so a foreign or anonymous caller is refused.
- #1926 written, not yet run: test/integration/mcp/combined_server_test.go
  drives a cluster node's MCP listener (port 8888) with the SDK MCP
  transport: tenant-operator readiness and a KV round trip, and an
  anonymous KV read refused. The pinned go-qrdb sdk/go has no constructor
  for the combined server (only `transport/mcp.NewInProcess` over a bare
  mcp-go server), so it runs against docker, not in-process. The lane has
  no docker: `make integration-test-mcp` is for lane-verify.

## Out of scope

- The go-qrdb pin bump itself (#1389); slices that need a seam absent from
  the pin stop and report it.
- Any tool's semantics beyond its permission, listing and wire fields.
