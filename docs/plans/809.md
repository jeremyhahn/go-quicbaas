# Plan: #809 prompts(4/4): Prompts page, TypeScript client, job prompt refs

## Objective

Operators edit orchestrator prompts at runtime from the web UI: pick the
tenant or project scope and the sdlc or workflow set, see what is
overridden here or inherited, edit with a placeholder legend, save with a
note, view history, roll back, reset to the parent, diff against the
parent, preview the effective prompt with its chain. The job page lists
the prompt versions a job ran with.

## Slices, in order

1. TypeScript SDK `PromptsClient` over REST (the eight `/api/v1/prompts`
   routes), the five other transports null-stub `prompts`. Taken from row
   #2372's commit, which is the same client on current main.
   Tests: `sdk/typescript/test/prompts.test.ts` (paths, query, bodies, 409).
2. `JobStatus.prompts?: PromptVersionRef[]` (the Go job status already
   carries `prompts`). Test: a job status read keeps its refs.
3. Frontend `src/lib/prompts.ts` helpers (origin badge, placeholder legend,
   diff line class, availability from 403/503, version-link parse/format)
   and `PromptsView.svelte` over the current client API, route
   `#/prompts?set=&project=`, nav item under SOFTWARE FACTORY, breadcrumb.
   Ported from the October #806 branches (issue/1723a), which used an older
   client shape. Tests: `promptsLib.test.ts`, `PromptsView.test.ts`,
   router and page-header consistency.
4. `JobDetailView.svelte` Prompts group: `set/name · scope · vN · hash8`,
   each linking to the Prompts page at that version.
   Test: `JobDetailView.prompts.test.ts`.
5. Rebuilt `dist/` (both copies); docs (`user.md`, `prompt-sets.md` GUI
   section, `api.md` TypeScript row); changelog fragment.
