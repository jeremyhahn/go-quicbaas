3. **REST 404 (#74). Blocked on a go-qrdb seam.** Reproduced at the pinned
   go-qrdb v0.30.1: over the module's real registered surface and go-qrdb's
   real `RESTMiddleware`, `GET /api/v1/no-such-route` with a bearer this
   daemon minted answers `401 no_peer_cert`. `RESTRouteRegistry.FallbackFor`
   consults a module's auth fallback only for a path some route registers,
   so on an unknown path the module's bearer is never read. The 401 for an
   anonymous caller is go-qrdb's disclosure order and stays. The fix is
   go-qrdb's: widen `FallbackFor` to a module's claimed prefix
   (`RegisterModulePrefix`), then a pin bump here. A handler of our own in
   front of the chain is ruled out (row: no parallel auth). Test, when the
   seam lands: `pkg/apimodule` e2e, unknown path, minted bearer -> 404,
   anonymous -> 401.
4. **Rate limiting (#816). Blocked on a go-qrdb seam.** REST is rate limited
   by default today (1000 req/s, `-1` opts out) by our own REST-only
   `rateLimiter`. go-qrdb v0.30.1 has the centralized limiter (go-qrdb#201:
   `pkg/ratelimit`, per-permission policies, enforced in every transport's
   `authorize()`), but only as `pkg/auth/middleware` options
   (`WithRateLimiter`, `WithRateLimitPolicies`); neither `sdk/go` nor
   `pkg/server` lets an embedder install them on the node's chain. Needs that
   `With*` option in go-qrdb and a pin bump; then our limiter is deleted.
   Tests: config default, opt-out, 429 on every transport go-qrdb limits.
   The acceptance line "REST rate limiting on by default, with an opt-out"
   holds today: `TestServer_GlobalRateLimitIsOnByDefault`,
   `TestServer_RateLimitOptOutDisablesGlobalLimiter`,
   `TestBindRoute_RateLimitOptOutCoversModuleRoutes` (`pkg/api/rest`),
   `TestBuildRESTServer_CarriesRESTRateLimit` (`pkg/server`) and
   `TestLoadFromFile_RESTRateLimit` (`pkg/config`). Only the move onto
   go-qrdb's limiter (#816) remains.
5. **Unified auth chain (#1144, #1153).** go-qrdb's tenant and authentication
   chain (and go-xkms auth) on every transport; the unified gRPC tenant gap
   closed; the parallel interceptors deleted. Tests: per-transport tenant
   from the mTLS peer, cross-tenant refusal, integration on every transport.
   Where it stands at go-qrdb v0.30.1:
   - Tenant from the mTLS peer already applies go-qrdb's rule
     (`TenantFromClientCert`) on the legacy gRPC/Unix listener
     (`grpcapi.UnaryTenantInterceptor`) and on the module's unified transports
     (`apimodule.peerTenantContext`).
   - The two still differ, and both differences change tenant binding on the
     legacy gRPC listener, which is on by default (`server.grpc.enabled`,
     port 9443). They wait on a ruling. (a) With `iam.spiffe_trust_domain`
     unpinned (the default), the legacy listener accepts a SPIFFE SAN under
     any trust domain, while the module binds nothing; go-qrdb says "a
     composer must pin its domain". The choice is between refusing to start
     and binding nothing. (b) A certificate naming no tenant is refused on
     the legacy listener, while go-qrdb's middleware folds it onto the
     system tenant.
   - Authorization on the legacy listener is our own platform-token gate
     (`grpcapi.UnaryAuthorizationInterceptor`), not go-qrdb's `AuthMiddleware`.
     `sdk/go` re-exports the `AuthMiddleware` type and `WithAuthMiddleware`
     but no constructor. The unified server already runs go-qrdb's chain over
     the module (`WithModule`), so deleting the parallel interceptors means
     retiring `startGRPCServer` in favour of the unified gRPC listener.
6. **TypeScript SDK families (#812).** projects, sdlc, accounts and prompts
   served on every TS transport that serves verbs. Vitest per family.
   Done: REST and MCP carry all four (prompts over `/api/v1/prompts/...` and
   the `prompt_*` tools, `test/prompts.test.ts`); gRPC-Web, QUIC, Unix and
   Wails refuse each with `TransportNotSupportedError` until items 7 and 8 land.
7. **gRPC-Web (#1529, #1533).** Blocked until the go-qrdb tag carries the

   stays, with a test that every verb refuses.
8. **QUIC / WebTransport (#1530, #1534).** Blocked on go-qrdb#1243 (WebTransport
   on the unified HTTP/3 listener) and a ruling on request framing; slices as in
   `docs/plans/1534.md`. Until then `TransportNotSupportedError` on every verb.
