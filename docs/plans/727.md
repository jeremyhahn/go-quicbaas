# Plan: #727 — delete JobRunConfig.Policy and JobRunConfig.Validators

## Objective

`JobRunConfig.Policy` and `JobRunConfig.Validators` are read by production
(`newJobRun`, `JobRun.Policy()`, `JobRun.Validators()`) and written only by
tests (Policy) or by one test (Validators). Ruling 189 (clean-code.md §1.3):
delete both; the operator's lifecycle policy reaches a run only through the
agent service (`JobLifecyclePolicyProvider`), the one path production uses.
The `WithDefaults` asymmetry of the explicit branch of `JobRun.Policy()` goes
away with the branch.

## Slices

1. Delete the fields (one commit).
   - `pkg/orchestration/job_run.go`: drop `Policy` and `Validators` from
     `JobRunConfig` and from `newJobRun`; `JobRun.Policy()` resolves from the
     agent service only.
   - Tests: `jobLaunch.Policy` seam removed. The five sites that set it (and
     `job_envelope_test.go`'s one `JobRunConfig.Policy`) carry the policy on
     the agent service: `controlLoopMockService` gains a `lifecyclePolicy`
     field and implements `JobLifecyclePolicyProvider` (a zero policy is
     what a non-provider resolves to, so no other test changes).
     `policyProvidingService` folds into it.
   - `job_run_provenance_test.go`'s `Validators:` sets the run's registry
     directly, as `validation_bound_test.go` already does.
   - New test `TestJobRunConfig_PolicyOnlyFromTheAgentService`: the config
     has no `Policy`/`Validators` field, and a service policy setting one
     stage bound runs every other stage at its default.

## Verification

- `pkg/orchestration` has no `Policy:`/`Validators:` writer into
  `JobRunConfig` left.
- `make` unit target for `pkg/orchestration` (race, count=3 for the #687
  property); `TestControlLoop_HookSetFromTheEnvelopeAndTheOperatorPolicy`
  and its siblings still prove the operator policy reaches the loop.

## Out of scope

- A per-job or per-tenant policy override (nothing asks for one).
- The run's internal `validatorRegistry` field, which tests set directly.
- No changelog: callers outside the package see no change.
