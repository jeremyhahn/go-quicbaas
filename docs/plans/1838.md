# Plan: #1838 release-signing-key, the code slice of #1827

## Objective

Re-export go-xkms's per-repository signing-key naming (go-xkms#1697,
shipped by #1705 in v0.64.0-alpha) through `sdk/go`'s Security() surface,
and wire it on REST, gRPC, QUIC, MCP, Unix and embedded. The tenant release
key is the default. go-quicbaas keeps no signing-key binding of its own.

## Blocker (2026-11-13)

The re-export needs go-xkms (and go-xkms/sdk/go) v0.64.x; main pins
v0.49.1-alpha. The pin bump is #1389, CA lane p1389c, branch
`deps/1389-xkms-v0642-qrdb-v051` (WIP, the build does not pass):

- go-xkms v0.64.2-alpha and go-qrdb v0.51.0-alpha require go-enclave
  v0.8.0-alpha, which dropped MemoryEnclave.Open.
- go-libsignal v0.3.1-alpha, its newest release (checked with
  `go list -m -versions` on 2026-11-13), still calls Open.

No slice of this issue can build until #1389 lands on main. This row
branch carries only this plan until then.

## Slices, in order, once #1389 is on main

1. Rebase this row on main with the v0.64 pin. Find the go-xkms sdk/go
   naming API (the #1705 binding) and re-export it from sdk/go's
   Security() surface: name a key for a repository, resolve a
   repository's key (the tenant release key when none is named), and a
   typed refusal for an invalid key name.
   Tests: unit tests in sdk/go for name, fallback and refusal.
2. Wire the verbs on every transport: REST handler and route, gRPC
   (proto + server), QUIC, MCP tool, Unix socket and embedded client.
   Tests: per transport, name a key for repository A and show that
   repository B falls back to the tenant release key; an invalid name
   gets the typed refusal. The feature's `make integration-test-<feature>`
   drives the CLI on all six transports.
3. Changelog fragment `changelog.d/release-signing-key.md` (callers see
   new verbs). Coverage of 90% or more on the changed packages.
