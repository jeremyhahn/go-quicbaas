# Plan: #195 orchestration-volumes

## Objective

SPEC row `orchestration-volumes` (docs/SPEC.md): go-blockstore volumes in
container orchestration over the VolumeProvider surface (create, grow-only
resize, attach to a device path, promote/demote). Services declare volumes in
their manifest; the fleet node agent attaches them at launch. The boot node's
NBD export consumes the attached volumes through `sdk/go`. go-blockstore adds
no NBD code and go-quicbaas adds no NBD server: go-trusted-platform's boot node
(a broker-class service) owns the export.

## Dependency

`github.com/jeremyhahn/go-blockstore v0.4.0-alpha`, the newest tag whose
go-enclave requirement (v0.5.0) stays at or below the held pin v0.6.1-alpha
(#1389). v0.5.0-alpha needs go-enclave v0.8.0, so it waits for the #1389 bump.

## Slices

1. **Volume surface** (`pkg/orchestration/volumes.go`, this slice).
   - Aliases for go-blockstore's VolumeProvider, ReplicatedProvider, VolumeSpec,
     VolumeStatus, AttachInfo, NodeID, and the error sentinels.
   - `NewVolumeProvider(name, settings)` over go-blockstore's factory.
   - `VolumeClaim` (name, size, fs type, container target, read-only,
     replicas, labels) with `Validate`.
   - `VolumeAttacher`: Ensure (provision or grow-only resize), Attach to the
     node's device path, Mount at a host staging dir, and emit a bind
     `ContainerMount`; raw claims (no fs type) report the device path only.
     `Release` unmounts and detaches in reverse. `Promote`/`Demote` pass
     through to a ReplicatedProvider and return ErrUnsupported otherwise.
     `Resize` refuses a shrink before reaching the provider.
   - Re-export in `sdk/go/orchestration`.
   - Tests: claim validation; provision-on-miss, reuse-on-hit, grow on larger
     claim, refuse shrink; attach/mount order and mounts emitted; rollback of
     earlier claims when a later one fails; release order; promote/demote on
     a replicated and a non-replicated fake; factory rejects an unknown provider
     and an unknown setting key.
2. **Launch wiring**: `ContainerSpec.Volumes []VolumeClaim`; the fleet node
   agent holds a VolumeAttacher (configured provider + node id) and attaches
   before `Run`, releasing on stop/remove and on a failed start. Tests on the
   agent's launch path with a fake provider.
3. **Raw devices for the broker class**: `ContainerSpec` device passthrough
   for raw claims, allowed only in the broker privilege class.
4. **Service manifest**: volumes in the `Service` manifest (row `services`)
   map onto claims; SDK `Compute().Services()` carries them.
5. **Coordinator + HA**: qrdb-backed `common.Coordinator` with a standalone
   fallback, injected into go-blockstore `pkg/ha` for replicated volumes;
   the conformance suite from gtp `issue/91-qrdb-coordinator` in the unit tier
   (SkipExpiredKeyReaping cites go-qrdb #174).
6. **Docs + SPEC**: `docs/orchestration/` volumes page; SPEC row status.
