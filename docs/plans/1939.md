# Plan #1939: regenerate the shipped console bundles

## Objective

The bundles shipped under `cmd/quicbaas/frontend/dist/assets/` (and the embed
copy under `pkg/api/rest/ui/dist/`) match a clean rebuild of the frontend
source, so the share-encoding fix in the source is what the console serves
(Codex 7740, PR #1845 round 11, P2).

## Slices

1. Run `make build-frontend` (the frontend build `make build` drives) on this
   branch and commit the regenerated dist assets. No source changes.
   Test: `make test-frontend` passes; a second clean rebuild leaves the tree
   unchanged (the bundles are what the source builds).

## Out of scope

- Source changes of any kind, including the share-encoding fix itself.
- #175 (`make build` dirties the working tree).

## Note

`main` and the PR #1845 branch share no history since the GitHub move; the
share-encoding fix is in that branch's source, not in `main`'s. On this row
branch (from `main`) the rebuild refreshes the bundles from `main`'s source;
the PR branch needs the same rebuild run on its own head.

## Blocked (2026-11-13)

`make build-frontend` on `main` runs green and is reproducible (a second
rebuild changes nothing), `make test-frontend` passes, and both dist copies
on `main` are stale. The lane's policy-guard refuses the commit: the new
`index-*.js` carries the SSH key textarea placeholder from
`src/views/security/ssh/ImportKeyModal.svelte` (an OpenSSH PEM header with an
ellipsis body), which the guard reads as a private key block. It is a UI
placeholder, not a credential. Open decision for the coordinator: allow it
past the guard for dist assets, or change the placeholder in the source
(outside this row's no-source scope).
