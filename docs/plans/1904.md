# #1904: transaction GETs never reach the write-only native encoder

## Objective

Codex 7453 P1 6 (PR #1845, head 08f0210, `pkg/service/quicbaas.go:2137`):
the #1845 translation forwards a transaction's GET as
`qrdbtransport.OpGet` to `ExecuteTransaction`. go-qrdb's `encodeServiceOp`
accepts only PUT and DELETE and encodes both branches before evaluating the
compares, so every transaction holding a GET fails, even in the branch not
taken. The kvMap test transport implements GET itself and masks it.

## State of main

main pins go-qrdb v0.30.1-alpha and does not carry the translation:
`transactionService.executeTransactionOps` serves GETs through
`executeGetOp` (KV read) and sends only PUT/DELETE to `Batch().ExecuteBatch`.
The finding's code exists only on the #1845 head (go-qrdb re-pin #1816), so
the fix itself lands once #1845 is on main (issue scope: "main after #1845
merges").

## Slices

1. (this lane) Real-node regression test,
   `pkg/service/transaction_real_node_test.go`: a mixed read/write
   transaction against `qrdbnode.Shared`, both branches holding a GET, once
   with the compare holding and once failing. It passes on main and fails on
   the #1845 translation, so it guards the merge.
2. (after #1845 merges) Rework the translation at the cited line so GETs
   never reach `ExecuteTransaction`: decide the compares and write branch
   natively with PUT/DELETE only, and serve the selected branch's GETs
   through the KV read seam after the commit (or a native read-transaction
   seam if go-qrdb has one at the new pin; if not, a ruling 159 seam issue
   on go-qrdb, which this row consumes). The slice 1 test must pass.

## Out of scope

The dependency bump itself (#1845) and the other Codex 7453 rows.
