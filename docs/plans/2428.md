# Plan: SPEC row daemon-rest-plane-authentication-and-authorisation (#2428)

## Objective

The go-trusted-platform daemon REST plane (go-trusted-platform#644) authenticates
and authorises through go-quicbaas `sdk/go` only (IAM, JWT, WebAuthn, PIV, mTLS,
RBAC/ABAC), with no auth model, route guard or token format of its own (owner
ruling 133). IAM invitations take the tenant and the user from the authenticated
principal, never from a request body (#1832, folded #1836).

## What already holds (checked in slice 2)

- Invite create: gRPC `IAMServer.CreateUser` resolves `req.TenantId` through
  `requireCallerTenant` (`tenantctx.Target`): a body tenant other than the
  caller's own is refused. REST `CreateUser` acts in the URL tenant, which the
  route guard binds to the principal (`tenantctx.AdminTarget`, #2342).
- Invite accept: the invitee has no credential yet; the invite token is the
  credential. `InviteStore.Lookup(tenant, token)` is tenant-scoped and the user
  id comes from the invite record, never from the request.

## Slices, in order

1. Plan (this file).
2. #1832/#1836 proofs: tests that
   - gRPC CreateUser with another tenant in the body is refused
     (PermissionDenied) and writes no user and no invite;
   - accepting tenant A's invite under tenant B's URL fails, and the activated
     user is the record's user.
   Done in slice 2: pkg/api/grpc/server_iam_invite_principal_test.go,
   pkg/api/rest/iam_invite_principal_test.go, and the rule in
   docs/iam/architecture.md. SPEC.md has no per-item tick; the row's PR
   marks the row shipped when every item holds.
3. Seam for go-trusted-platform#644: an `sdk/go` surface a foreign daemon's
   REST plane mounts to authenticate (bearer JWT / mTLS / PIV) and authorise
   (RBAC/ABAC permission check) a request through go-quicbaas, with a test
   that drives an `http.Handler` through it on every transport.
   Done in slice 2: `platformtoken.Validator.Middleware` / `AuthorizeRequest`
   (Bearer/DPoP token, DPoP proof, RFC 8705 x5t#S256 client-certificate
   binding, scope permission, principal from the token), with
   sdk/go/platformtoken/middleware_test.go. The guard is HTTP-only, so "every
   transport" means every way a token is bound (bearer, DPoP, mTLS/PIV
   certificate). Consumer docs: docs/iam/architecture.md "A downstream
   daemon's REST plane". Slice 3: tokens minted by the node's own issuer
   after a WebAuthn, a PIV and an mTLS login pass through the guard, with the
   role's RBAC permissions deciding the route
   (pkg/iam/daemon_rest_guard_test.go). Slice 4: a live node's client-credentials
   tokens (bearer and DPoP-bound) through the guard with the node's JWKS
   (test/integration/iam/daemon_rest_guard_test.go; compiled here, run by
   `make integration-test-iam` in CI, which needs Docker). Remaining: the scope match is the local matcher SPEC D5/D8 replace with go-qrdb's once
   re-exported (CA to say whether this row waits on that seam).
4. #1816 dependency: non-system tenant login through the SDK; record its state
   in docs/iam/ and the row (it waits on #1816; not done in this row if #1816
   is still open).
5. Row PR marks the row shipped in docs/SPEC.md.
