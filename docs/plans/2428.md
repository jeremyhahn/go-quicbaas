# Plan: SPEC row daemon-rest-plane-authentication-and-authorisation (#2428)

## Objective

The go-trusted-platform daemon REST plane (go-trusted-platform#644) authenticates
and authorises through go-quicbaas `sdk/go` only (IAM, JWT, WebAuthn, PIV, mTLS,
RBAC/ABAC), with no auth model, route guard or token format of its own (owner
ruling 133). IAM invitations take the tenant and the user from the authenticated
principal, never from a request body (#1832, folded #1836).

## What already holds (checked in slice 2)

- Invite create: gRPC `IAMServer.CreateUser` resolves `req.TenantId` through
  `requireCallerTenant` (`tenantctx.Target`): a body tenant other than the
  caller's own is refused. REST `CreateUser` acts in the URL tenant, which the
  route guard binds to the principal (`tenantctx.AdminTarget`, #2342).
- Invite accept: the invitee has no credential yet; the invite token is the
  credential. `InviteStore.Lookup(tenant, token)` is tenant-scoped and the user
  id comes from the invite record, never from the request.
