# Plan: SPEC row `projects` (#1679)

## Objective

Ship the `projects` row of docs/SPEC.md: its three acceptance items hold, and
the folded #1303 (a bind that commits between DeleteProject's binding check and
the delete leaves a binding on a deleted project) is closed.

## State at the start of the row

- The tenant-scoped project record is in `pkg/orchestration` and
  `pkg/service/project_service.go`, documented in `docs/projects/`.
- A bound delete is refused with `service.ProjectBoundError` (`run unbind`).
- Name arbitration admits one winner across nodes.
- Open: #1303, listed as a known gap in `docs/projects/architecture.md`.

## Slices, in order

1. **Delete fence (#1303).** `sdlc.Store` gains a per-project delete fence in
   the tenant KV beside the bindings. Each side writes its mark, then reads the
   other's, so a delete and a bind never both succeed.
   - `FenceProjectDelete` admits one delete at a time (`DeleteInProgressError`,
     409); only an absent or stale (`DeleteFenceTTL`) fence is replaced.
   - `DeleteProject` fences, checks for a binding, deletes, and turns its fence
     into a never-stale tombstone (`MarkProjectDeleted`, token-checked).
   - `PutBinding` stamps a `WriteToken` and returns the record it replaced;
     `Bind` reads the fence after every write and withdraws its own write by
     token (a rebind restores the prior), returning `ProjectDeletingError`.
   Tests: fence round trip, staleness, tombstone, token checks, withdrawal;
   the hooked bind/delete race through `SDLCService.Bind`.
2. **Settlement fixes (review of slice 1), one commit each:**
   1. Per-project bind lease (`AcquireBindLease`/`ReleaseBindLease`,
      `BindLeaseTTL`, `BindInProgressError` mapped to 409 / FailedPrecondition
      / ErrConflict). Test: `pkg/sdlc/store_bind_lease_test.go`.
   2. `Bind` and `Unbind` hold the lease from before `retirePriorDelivery` to
      the last write, released on a detached context. Test: two interleaved
      binds; the second is refused and writes nothing.
   3. `Bind` pre-checks the fence before retiring the prior delivery; a
      withdrawal that restores a prior binding onboards it again (failure is
      `BindWithdrawError`). Tests: rebind behind a fence refused with no
      offboard; a fence after the pre-check re-onboards the prior.
   4. A failed `store.Delete` re-reads the project: gone settles a tombstone,
      present clears the fence, an unreadable store leaves it held. Tests:
      delete that removes then fails leaves a tombstone; failed Delete and Get
      leave the fence held.
   5. Review of round 2: a bind with no live fence re-reads the project and
      withdraws if it is gone; a tombstone that cannot be written returns
      `ProjectDeleteUnsettledError`; `BindInProgressError` maps to
      FailedPrecondition in the SDLC gRPC converter; the store clock stays
      unexported and the service tests age the stored record. Tests: unsettled
      tombstone with a late bind; bind and unbind RPCs under a held lease.
   6. Review of round 3: `Store.SettleBindingWrite` settles a binding write
      with an unknown outcome: the write's token means it landed; otherwise
      the slot gets a void marker (empty slot) or the held record re-stamped,
      so the pending compare-and-swap can never apply. Listing skips void
      markers. `Bind` settles every unknown write before the fence read, and
      a fresh bind that did not land forgets its route. Tests hold the write
      back and commit it after the bind (and a delete) returned: it does not
      apply and no binding or route is left.
3. **Docs and ship.** Remove the known gap from `docs/projects/architecture.md`,
   document the fence, lease and errors in `docs/projects/`, tick the row's
   items, and mark the row shipped in `docs/SPEC.md`.

## Out of scope

- Any change to the project record's schema or to name arbitration.
- Cascading delete into offboarding: delete still refuses a bound project.
