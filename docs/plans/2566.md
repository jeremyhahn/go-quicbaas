# Plan: #2566 — a Unix caller with a verified administrator certificate is authenticated as over TCP

## Objective

`TestAdminFactors_PasskeyEnrollsThenLogsIn/unix` (test/integration/login) fails
with `Unauthenticated` on `GetUserByUsername`: over TCP the embedded qrdb
node's auth middleware turns a verified client certificate into a principal,
while quicbaas's own gRPC server on the Unix socket (`authorizeGRPCRequest`,
`pkg/api/grpc/authz_interceptor.go`) demands a bearer and never looks at the
certificate. A Unix caller with a verified administrator certificate must be
authenticated exactly as it is over TCP: same revocation, mTLS binding policy,
peer attestation and RBAC/ABAC decision.

## Slices, in order

1. Failing test (done, PR #2582): `pkg/api/grpc/authz_interceptor_unix_mtls_test.go`
   reproduces the refusal in a unit test.
2. Certificate seam in the PEP (done, PR #2582): a bearer-less call whose TLS
   handshake verified the client chain is offered to an authorizer that
   implements the optional `GRPCVerifiedCertificateAuthorizer`
   (`pkg/api/grpc/authz_validator.go`) and checked against the method's mapped
   permission. IdentityGated verbs still need a token; an authorizer without
   the seam, or a certificate that is not chain-verified, keeps the call
   `Unauthenticated`. Tests: the unit tests of slice 1, plus the fail-closed
   cases in the same file.
3. Production implementer of the seam (blocked): back
   `AuthorizeVerifiedCertificate` with the embedded node's own certificate
   authentication, so Unix and TCP cannot drift. Test:
   `make integration-test-login` (`TestAdminFactors_PasskeyEnrollsThenLogsIn/unix`
   passes on every transport).

## Blocker for slice 3

quicbaas has no handle on the node's auth middleware: neither `sdk/go`,
`sdk/go/node` nor go-qrdb's `pkg/server` exposes it. Building a second
middleware from copied wiring could miss the revocation checker and admit
certificates on Unix that TCP refuses. It needs go-qrdb to export the node's
certificate authentication (or the middleware), or a decision to serve Unix
through the node's own listener.

## Out of scope

- Any change to the TCP path or to the node's middleware itself.
- Bearer-token behaviour on either transport.
