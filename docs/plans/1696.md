# Plan: SPEC row `deployment` (#1696)

## Objective

QuicBaaS ships a Kubernetes deployment and a truthful production checklist,
and every node of the 3-node Raft cluster runs one go-quicbaas tag; formation,
smoke and failover pass.

## Slices, in order

1. **#2232 compose health and runtime image** — done by #2265: compose
   healthchecks hit `/api/v1/health/live` (route test in `pkg/api/rest`), and
   the runtime image's docker CLI and git are covered there.
2. **Kubernetes manifests and checklist** — `deployments/kubernetes/`
   (kustomization pinning the one release tag, set by the operator to a release that serves REST, a 3-replica
   Parallel StatefulSet with OnDelete updates rolled through the PDB by
   `rolling-upgrade.sh`, stable DNS Raft membership, a headless Service
   with publishNotReadyAddresses, a PDB with minAvailable 2, hostname
   anti-affinity, a NetworkPolicy, HTTPS probes on `/api/v1/health/live` and
   `/ready`). Tests:
   - `test/buildgates/kubernetes_test.go`: tag pin, formation shape,
     one-node-loss shape, ports against the ConfigMap.
   - `cmd/quicbaasd/kubernetes_config_test.go`: the daemon loads the
     ConfigMap plus a pod's exports as Raft node 2.
   - `pkg/api/rest/health_paths_test.go`: probe paths are served routes.
   The daemon binds `QUICBAAS_RAFT_TLS_{CERT,KEY,CA}_FILE`, so per-pod
   certificates arrive without file keys. The checklist's fictional discovery
   section becomes the real membership configuration.
3. **Guide** — rewrite `docs/deployment/kubernetes.md` around
   `deployments/kubernetes`: secrets, the tag pin, formation, probes,
   failover, upgrades. Also fix the checklist's leftover gRPC 9090 and second
   `discovery:` block. The guide renews a Raft certificate on the replica's
   existing key (a new key is a membership change the manifests do not do);
   `TestKubernetesGuideRenewsRaftCertificatesOnTheirKey` holds it.
4. **3-node formation, smoke and failover on one tag** —
   `make integration-test-cluster-failover` (Docker) builds the node image
   once with VERSION and the commit compiled in, and starts three nodes on
   that one tag. `TestDeploymentProof_OneBuildFormsAndServes` checks one
   build, formation and smoke; the target then stops the leader, and
   `TestDeploymentProof_AfterLeaderStop` checks failover. Both carry the
   `deployment_proof` tag. `test/buildgates/cluster_proof_test.go` holds the
   compose, Dockerfile and target shape. The run's output on a Docker host is
   the evidence; ticking the row in `docs/SPEC.md` follows that run.

## Out of scope

Helm charts and operator-based discovery. The stale `integration-test-minikube`
Makefile target (it references the deleted `pkg/discovery/testdata`).
