# #1801 — bootstrap / IAM: every backend's first-boot admin authenticates

## Objective

TestBackendMatrix and TestCanonicalInit_Matrix prove, on every storage
engine (memory, file, pebble) and every transport (rest, grpc, quic, mcp,
unix), that the administrator first boot issued can authenticate: the SDK's
Health.Liveness and a data round trip, with no backend special-cased.
go-qrdb's MCP server refusing an uncredentialed initialize stays (CA ruling
571); first boot stays go-qrdb's (rulings 538, 539).

## Finding (slice 1)

The memory skip in runBackendCell rested on a wrong premise. On a memory
node, `quicbaasd start` finds no administrator and runs the same qrdb
first-boot path (`Server.firstBootBootstrap` -> `qrdbsdk.BootstrapSystem`)
in the serving process, and writes a fresh admin bundle to
`<data-dir>/admin/` exactly as init does on a durable engine. With the skip
removed, memory_rest passes the authenticated round trip locally.

What actually failed was every `*_mcp` cell, on every backend and strategy:
the matrices dialled MCP's Health.Liveness without a credential, and the MCP
server correctly answers 401 on initialize.

## Slices

1. Test harness (this slice):
   - `loginFirstBootAdmin` (backend_matrix_test.go): mTLS login as the
     first-boot admin over the transport under test; returns the stored
     session token.
   - `newSDKClient` / `verifySDKLivenessOverTransport` take that token and
     the MCP client presents it (`WithMCPAuthToken`).
   - runBackendCell: login, then liveness, then round trip, on every backend;
     the memory "skipping the authenticated round trip" branch is gone.
   - runMatrixCell: logs in before the SDK liveness the same way.
   - Tests: `make integration-test-init` (no Docker) covers every cell.

## Out of scope

- Any change to MCP authentication or to go-qrdb's first-boot API.
- Making memory-engine state survive a process restart.
