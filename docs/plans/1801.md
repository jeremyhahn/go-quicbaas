# #1801 — every transport answers a node, sealed or not

## Objective

TestBackendMatrix and TestCanonicalInit_Matrix prove, on every storage
engine and every transport (rest, grpc, quic, mcp, unix), that the node
answers the SDK's Health.Liveness, including a shamir node that boots
sealed. MCP auth stays (ruling 571); qrdb owns the plumbing (538, 539).

## Done earlier

- Matrix harness logs in as the first-boot admin (REST, mTLS) and MCP
  liveness carries that session; the memory-engine skip is gone.

## Slice 2 (this slice): sealed gRPC serves quicbaas.v1.QuicBaaS

Finding: `/quicbaas.v1.QuicBaaS/Health` is on the sealed-window allowlist,
but `startSealedGRPCServer` registered only the barrier/ceremony mirrors
and qrdb.v1, so grpc and unix answered "unknown service
quicbaas.v1.QuicBaaS". The sealed server now registers the QuicBaaS
service over the sealed-window facade; the sealed-window interceptor still
refuses every off-allowlist verb. After unseal the full boot registers the
operational service as before.

- Test: TestSealedBoot_GRPCServesQuicBaaSHealth (pkg/server, rest tag):
  a sealed node answers Health on its unix gRPC socket over TLS; Get stays
  refused. Red before ("unknown service"), green after.
- `make integration-test-init` for the shamir grpc/unix cells.
