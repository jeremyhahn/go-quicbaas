# Plan: #1171 workflows mount the host Docker socket (IS-12)

## Objective

No job a pull request can reach gets the runner host's Docker daemon, and
release builds use images pinned by digest. Owner ruling 130 (relayed on the
issue 2026-10-25) splits it:

- **A (now, this lane):** `.github/workflows/release.yml` runs its jobs on
  the forge's dedicated `release` runner label, and pins the build and scan
  images by `@sha256` digest.
- **B (later):** taking the host socket away from PR jobs (`ci.yml`) is
  runner-side isolation, owned by Infrastructure.

State of `ci.yml` on main: since ci-template v1.34.1 it mounts no Docker
socket (the publish-images job already runs on `release`), so the
`ci.yml:914` evidence no longer holds and needs no edit here.

## Slices

1. **release.yml on the release runner, pinned images, no socket mount.**
   - Every release.yml job: `runs-on: ${{ github.server_url ==
     'https://github.com' && 'ubuntu-latest' || 'release' }}` -- the form
     ci.yml's publish-images job uses (GitHub has no `release` runner).
   - Workflow env pins `TRIVY_IMAGE` (aquasec/trivy at the toolchain's
     TRIVY_VERSION, v0.76.0) and `GO_BUILD_IMAGE` (golang 1.27.4-bookworm)
     by digest; the binaries build and the three Trivy gates use them.
   - The Trivy gates scan a `docker save` tarball copied into the scanner
     container (`docker create` / `docker cp` / `docker start -a`, the
     pattern build-binaries uses) instead of mounting the daemon socket.
   - Test: `test/buildgates/docker_socket_test.go`
     - no workflow bind-mounts `docker.sock`;
     - every release.yml job runs on the release expression;
     - every image release.yml runs is pinned by `@sha256:<64 hex>`.
     Fails on main (three socket mounts, `ubuntu-latest`, `:latest`),
     passes after.
   - docs/SPEC.md row `release-readiness`: the criterion reads as what
     holds now (no workflow mounts the socket; release on the release
     runner, pinned images).

## Out of scope

- Runner-side isolation of PR jobs (ruling 130 option B, Infrastructure).
- Digest pins on the Dockerfile base images (`golang:${GO_VERSION}-alpine`,
  `alpine:3.24.1` in Dockerfile and Dockerfile.cli): outside this lane's
  file map; reported for a follow-up.
- Makefile's local `docker-scan` target (developer machine, not CI).
