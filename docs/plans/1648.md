# Plan: SPEC row `composition` (#1648)

## Objective

go-qrdb and go-xkms are composed into go-quicbaas as released libraries:
go-xkms adapters are injected into an embedded-only go-qrdb node, the pins
are released tags, the module route-collision guard is order-independent,
the go-qrdb#927 and #928 seams are consumed through `sdk/go` alone, and the
Composition clean-up table (C1) in docs/SPEC.md is empty. The row's one PR
marks the row shipped in docs/SPEC.md and closes #1648.

## Slices, in order

1. **Fold #2249 (#1617, folded #1621): remove the dead `qrdb.transport`
   setting.** Merge `issue/i1617b` with a merge commit. The `qrdb:` config
   block is gone and a config that carries it is refused
   (`pkg/config/loader_removed_qrdb_test.go`); the remote transport factory
   and the ShardedClient options for a remote daemon are removed
   (`pkg/server/sharded_client_node_test.go`,
   `sharded_client_detached_test.go`). C1 in docs/SPEC.md is empty.
   Tests: unit tests of `pkg/config`, `pkg/server`, `pkg/service`.
2. **#2388 accounted for.** Done: its composition part is #2249 (slice 1),
   carried in this branch. The rest of #2388 (health paths, the rag
   watcher, label strings, security tests, build files) belongs to other
   rows and is not folded here.
3. **Route-collision guard is order-independent.** A test registers the
   same module set in two orders and gets the same collision verdict
   (`pkg/server`, near the node builder's route guard in `qrdb_node.go`).
   Done: both sets are claimed by module name (`inClaimPrecedence`);
   `module_host_order_test.go` checks every ordering.
4. **Pins.** go.mod pins released go-qrdb, go-qrdb/sdk/go and go-xkms tags
   (no pseudo-versions); a build-gate test refuses a pseudo-version pin.
   Gate done: `test/buildgates/composed_pins_test.go` refuses a
   pseudo-version, a non-semver pin, a local-path replace or a missing
   requirement for every go-qrdb and go-xkms module required by go.mod
   and sdk/go/go.mod, and `TestComposedPinFilesNameEveryRequiredComposedModule`
   keeps that list complete; today's pins (go-qrdb and sdk/go
   v0.30.1-alpha, go-xkms v0.49.1-alpha) are released tags.
   A pin bump past go-xkms v0.52 is blocked upstream (from the #1393 fold,
   2026-11-13): go-xkms v0.55 `pkg/backend/avr` needs the private module
   `arduino-generic/sdk/go` v0.7.0-alpha (proxy 404; node-prep must seed
   it), and go-libsignal v0.3.1-alpha calls `MemoryEnclave.Open`, which
   go-enclave v0.8 (needed from go-xkms v0.52 on) removed. The target pin
   set is epic #2370's (go-xkms v0.64.2, go-qrdb v0.58.2), not #1393's
   v0.55/v0.47; it needs the owner's decision.
   Consumer migration: go-quicbaas's own code is being moved to the pinned
   set (go-qrdb v0.51.0, go-xkms v0.64.2) package by package. Two parts
   wait on decisions: go-libsignal v0.3.1-alpha does not build against
   go-enclave v0.8.0-alpha and needs a go-libsignal pin decision; and
   `pkg/service` calls the barrier rekey, recover-with-keys, root-token and
   tenant unseal-progress operations that go-qrdb v0.51 removed with no
   replacement. go-qrdb v0.51 also removed `ResolveSystemRoleID`, which the
   `pkg/iam/qrdbadapter` role-name resolver tests call.
5. **go-xkms adapters injected into go-qrdb**, embedded node only, one node
   per process: a test proves a second node in the same process is refused.
   Landed: a process-wide slot (`qrdb_node_slot.go`) that
   `initStandaloneQRDBNode` and `initClusteredQRDBNode` claim before building
   (before the seal strategy, so a refused Server opens no TPM session), and
   that `stopQRDBNode` and a failed construction release. The refusal is
   `EmbeddedNodeRunningError`, proved by `qrdb_node_slot_test.go`.
   `pkg/server`'s own test binary runs with an unbounded slot (`main_test.go`)
   and the guard's tests swap a real one in. The iam bootstrap and
   orchestrator embedded-spawn integration suites, which boot a second Server
   beside their package's shared TestMain Server, now run in packages of
   their own (the iam self-registration matrix, which boots through the
   bootstrap helpers, moved with them). The go-xkms adapters are already in
   the tree:
   `buildXKMSCryptoOptions` (`pkg/server/qrdb_node.go:344`) and the go-xkms
   ServiceModule (`:682-709`) that both node builders receive.
6. **Seams go-qrdb#927 / #928** (consumer side): the sealed-window proxy
   uses `sdk/go`'s `compaction.Policy` alias, and the embedded client's
   index service comes from `sdk/go`; go-quicbaas imports no
   `pkg/compaction` or `pkg/service` of go-qrdb. Blocked until a go-qrdb
   tag carries them; until then #1619 stays a draft. Both seams are split
   out to follow-up rows, blocked on a go-qrdb tag that carries them.
   The #927 consumer side has landed: the sealed-window admin proxy
   forwards NodeCompaction / SetNodeCompaction through `sdk/go`'s
   `CompactionPolicy` alias. #928 is unchanged.
7. **Ship the row**: tick every item, mark the row shipped in docs/SPEC.md.
