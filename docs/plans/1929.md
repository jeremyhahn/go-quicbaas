# Plan: #1929, declare scheduler and placement permissions for delegated embedded calls

## Objective

Codex review 7595 P1 9 on #1845, at `sdk/go/embedded_identity.go:173`: a
delegated embedded client rejects any operation that has no entry in the
operation-permission map before it checks the grant. The map has no
`quicbaas.Scheduler` entries, so the scheduler and placement handlers that
`handlers_scheduler.go` registers (CreateJob, GetJob, the placement methods)
are always refused. Fix: declare the canonical `scheduler:*` and
`placement:*` permission for every registered scheduler method, the same
ones the gRPC methods already declare, and make sure the principal's grant
ceiling includes them.

## Slices, once the delegated embedded identity is on main

1. Failing test first (`sdk/go`): a delegated embedded client whose
   identity holds `scheduler:create` (or the canonical permission of each
   method) calls CreateJob, GetJob and a placement method. Each call must
   pass the undeclared-operation check and reach the grant check. Assert
   every `scheduler.Methods()` entry has a map entry equal to the
   permission its gRPC method declares (a table test, so a new method
   without an entry fails).
2. The fix: populate the operation-permission map for every registered
   scheduler and placement handler from the same source the gRPC
   declarations use, and widen the principal grant ceiling to cover them.
3. Run the `sdk/go` unit tests and `make integration-test-scheduler`.
