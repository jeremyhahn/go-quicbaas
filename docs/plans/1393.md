# #1393 composition: pin go-xkms v0.55.0-alpha and go-qrdb v0.47.0-alpha

## Objective

`go.mod` and `sdk/go/go.mod` require released go-xkms and go-qrdb tags that
carry the go-xkms#1531 FIPS fix (first released in v0.54.0-alpha), so
go-trusted-platform gets it through one go-quicbaas tag. The release takes
the next free tag (v0.16.0-alpha already exists).

## Status (2026-11-13): blocked upstream; no slice can build

Running `go get` for go-xkms v0.55.0-alpha, go-qrdb v0.47.0-alpha, go-auth
v0.5.1-alpha and go-signal v0.2.2-alpha resolves (go-enclave moves to
v0.8.0-alpha). `go build ./...` then fails before any quicbaas code compiles:

1. go-xkms v0.55 `pkg/backend/avr` imports
   `github.com/jeremyhahn/arduino-generic/sdk/go v0.7.0-alpha`. That module is
   private: proxy.golang.org returns 404 for it, and lanes have no forge
   credential. The module has to be seeded into the node's module cache
   (node-prep) before a lane can build.
2. go-libsignal v0.3.1-alpha, its newest release, calls
   `enclave.MemoryEnclave.Open`. go-enclave v0.8 removed that method, so
   `pkg/util/crypto/secret` does not compile. Every go-xkms tag from v0.52 on
   needs go-enclave v0.8 or later. The fix is a go-libsignal release built on
   go-enclave v0.8 or later; downgrading go-libsignal needs a ruling.

Prior work: the `issue/1389a-xkms-v055-pin` ledger (v0.55/v0.47, then
v0.60/v0.51), `deps/1389-xkms-v0642-qrdb-v051`, and epic #2370
(`row/2370-stack-pins`: go-qrdb v0.58.2 with go-xkms v0.64.2). The pin set
that is current in the 2370 epic supersedes v0.55/v0.47. The pin to target
needs a CA ruling.

## Slices, once unblocked

1. Pins: both go.mod files, with go-auth and go-signal following the cascade.
   Test: `go build ./...` and `make verify-api-shapes`.
2. Call-site migration (the issue's break list; rulings 1-3 of m706: barrier
   and ceremony pass-through, the SSH store re-enrol break, and the embedded
   least-grant service principal). Tests: the unit tests of each touched
   package; `make integration-test-<feature>` for barrier, ceremony and ssh.
3. Re-exports in `sdk/go/xkms/xkms.go` follow the lower layer: delete or
   re-point each alias, never recreate it locally. Test: the sdk/go alias
   check.
4. Docs: the deployment pins in `docs/go-sdk/engineering.md` and
   `changelog.d/composition.md`.
5. Release: tag from the first green main run after the merge, then run the
   scratch-consumer `go get` check (release-versioning §2).
