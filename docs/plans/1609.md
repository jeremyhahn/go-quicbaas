# Plan: #1609 TenantExists reads the tenant catalog in the system scope

## Objective

`orchestration.TenantResolver.TenantExists` (`iamTenantLister` in
`pkg/server/lifecycle_orchestration_sources.go`) finds a tenant that IAM
created, even when the caller's context is bound to a non-system tenant.
An unknown tenant is still reported as absent.

## State on main

The scope fix landed in #2342: `TenantExists` calls `GetTenant` with
`tenantctx.WithSystem(ctx)`, the scope IAM stores tenant records in.
`TestIAMTenantLister_TenantExistsReadsTheSystemCatalog` covers the known
tenant under a tenant-bound context. It fails without `WithSystem`.

## Slices

1. Tests: the catalog stub holds one known tenant.
   `TestIAMTenantLister_TenantExistsUnknownTenantFromInsideATenant` checks
   that an unknown tenant asked about under a tenant-bound context is
   reported as not existing, so the system-scope read cannot make every
   ID exist.

## Verification

- `make test-server` (the CI tag set) passes.
- `make integration-test-orchestrator` needs Docker; CI runs it (the 8
  cases in the issue).

## Out of scope

- The orchestration package's authorization; any new tenant model.
- Moving `test/integration/orchestrator` into the unit suite (#1600).
