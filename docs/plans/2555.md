# #2555: the invite endpoint answers 503 right after the server reports started

## Objective

`TestBootstrap_InviteEndpoint_IsPublic` (test/integration/iam) fails on main
with a plain-text 503, `quicbaas rest surface is not yet available (server
still composing)`. It comes from the apimodule lazy handler
(pkg/apimodule/module_http.go) while `ModuleRESTServer()` still resolves nil.

Root cause: `(*Server).initialize` sets `s.started = true` on entry
(pkg/server/server.go), before storage, the service facade, IAM attach
(`iamReady`) and REST. `IsStarted()` reports that flag, and callers use it as
the readiness signal (cmd/quicbaas `waitReady`, the integration helpers). So
`IsStarted()` is true while the server is still composing.

## Slices

1. `test:` a unit test in pkg/server/server_test.go. It records `IsStarted()`
   from inside the IAM init seam, while composition is still running. It
   requires false there, and true after `initialize` returns. It fails on
   0f80545b.
2. `fix:` pkg/server/server.go keeps `started` as the re-entry guard. It adds
   a `ready` flag that `initialize` sets only on its final successful return,
   and `IsStarted()` reports `ready`.

## Out of scope

- The apimodule lazy handler's 503 while composing (correct behaviour).
- The integration test itself: it already waits on `IsStarted()`.
