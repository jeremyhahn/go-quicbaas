# Plan: #1889 — delegated secret resolution authorizes once per request

## Objective

Codex review 7395 P1 4 on #1845 (`sdk/go/secret_resolver.go:79`): the bound
embedded client's `GetSecret` / `EnsureSecret` authorize `secrets:read` (and
`EnsureSecret` its write grant) up front, then dispatch `Secrets/GetData`
through the bound embedded transport, whose authorizer calls qrdb
`AuthorizeTenant` for the same permission again. qrdb takes a rate-limit token
per authorization, so under a `RatePerSecond:1, Burst:1` policy the first
resolution is refused. Fix: one authorization gate per logical request, with
the identity binding kept.
