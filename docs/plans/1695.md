# Plan: #1695 tenant-agent row

## Objective

The tenant-agent row in `docs/SPEC.md` and its `ROADMAP.md` line describe a
Tenant Agent that coordinates its tenant. PR #2462 carries the text; the
identity and key line (go-qrdb principal with tenant-scoped RBAC, go-xkms
signing key) is a recommendation for the owner to confirm or change in review.

## Slices

1. Row text: replace the row in `docs/SPEC.md` and the `ROADMAP.md` line
   (done, PR #2462). Docs only: no tests.
2. Finish PR #2462: merge `origin/main` (merge commit), so the `Lint` job's
   `deps-check` sees main's golang.org/x/oauth2 and golang.org/x/sys
   upgrades. Checks: `make deps-check`, `make check-build-tags`.

3. Owner approval (Codex P1 on 34b98f3aabf4): `docs/SPEC.md` line 6 says
   re-scoping a feature needs the owner's change to the file. The PR cannot
   merge until the owner approves the revised row (or changes it) and the
   approval is recorded on PR #2462. The owner approved the row text, with
   the identity and key line as written.

4. Tenant Agent foundation (this PR). Three packages:
   - `pkg/iam`: `EnrollTenantAgentIdentity` and `RevokeTenantAgentIdentity`
     converge an mTLS-only go-qrdb certificate principal holding the
     per-tenant role `tenant-agent` (`role-tenant-agent-<tenant>`), which
     holds exactly the pinned read-only `TenantAgentGrant()`: the agent
     session floor plus `agents:read`, `sdlc:read` and `spend_report:read`.
     They refuse to promote or delete any other principal.
   - `pkg/orchestration`: `TenantAgent` and `TenantAgentStore` keep one
     appointment per tenant under a fixed record key, metadata only, audited.
   - `pkg/tenantagent`: `Service` appoints, retires, signs and verifies.
   Guarantees:
   - one Tenant Agent per tenant, enforced by the record key and by
     `Appoint`'s principal check before anything is enrolled;
   - it runs as a catalog agent declaring the lead role, or a pool whose
     every member does;
   - an mTLS-only principal with role `tenant-agent` and the pinned
     read-only grant;
   - signing key `tenant-agent-signing-<tenant>`, through go-xkms, separate
     from the policy-signing key;
   - context-scoped isolation: every call names one tenant and refuses a
     context scoped to another;
   - compensation: a failed appointment write revokes the fresh principal.
   Checks: `gofmt -l`, `go vet`, `go test -race -count=1` (plain and with
   `$(make -s print-TEST_TAGS)`) on `./pkg/iam/... ./pkg/orchestration/...
   ./pkg/tenantagent/...`, `make check-build-tags`, `make lint`.

5. Priorities and milestones:
   - `pkg/orchestration`: `TenantPlan` (ranked project priorities and
     milestones, bounded in size) and `TenantPlanStore` keep one plan per
     tenant under a fixed record key, written by revision compare-and-set,
     audited.
   - `pkg/tenantagent`: `Planner` writes a plan only with a standing
     appointment, resolves every named project in the tenant's
     `ProjectStore`, signs the plan with `tenant-agent-signing-<tenant>`
     over a payload naming the tenant, revision, principal and key, and
     verifies it on every read. A retirement keeps the plan readable.
   Checks: as slice 4.

6. Owner reports (this PR): `pkg/tenantagent` `Reporter` builds the owner's
   report with a standing appointment, from the tenant's verified plan, its
   projects and its tasks: projects by rank with task counts per status and
   needs-owner and escalated counts, milestone states (done, open, overdue)
   against the clock. It is signed with `tenant-agent-signing-<tenant>`;
   `VerifyReport` checks it. Checks: as slice 4.

## Out of scope

- Tenant Agent behaviour beyond appointment, identity, signing, the plan and
  the owner report: triage, staffing and directing project agents, and any
  transport surface or delivery of the report (later slices).
