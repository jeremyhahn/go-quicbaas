# Plan: #628 — `sdlc.verification_commands` is validated, documented and read by nothing

## Objective

`sdlc.verification_commands` is loaded, defaulted and validated, and nothing
reads it. Ruling 189 (DS-3821): delete it, since the SPEC row gives it no
meaning. A configuration that still sets it is refused at load **by name**,
with where the setting went, like the other removed keys.

## Slice 1 (this lane)

- `pkg/config/config.go`: drop `SDLCConfig.VerificationCommands` and the doc
  comment that describes a canonical sdlc workflow that no longer exists. Add
  `sdlc.verification_commands` to `RemovedKeys`. The replacement names
  `orchestration.verification_commands` (the allowlist) and the binding's
  `verification` list (what a project runs). Fix the `SDLCKeys` comment that
  calls it file-only list configuration.
- `pkg/config/defaults.go`: drop the default.
- `pkg/config/validator.go`: drop its validation.
- `pkg/config/validator_test.go`: drop the empty-command case.
- Test: `TestLoad_RefusesSDLCVerificationCommands` loads a file that sets the
  key and asserts the `RemovedKeyError` names it and both replacements. It
  fails before the change, because the key loads silently. The table test
  `TestLoad_RefusesRemovedKeysByName` covers it as well.
- Docs: `docs/sdlc/engineering.md` loses the key from the example `sdlc:`
  block. `changelog.d/628-sdlc-verification-commands-removed.md` (Removed),
  because an operator's file that sets the key now fails to load.

## Out of scope

- `orchestration.verification_commands` and the binding's `verification`
  list: unchanged.
- `pkg/server/lifecycle_sdlc.go`, `lifecycle_orchestration_sources.go` and
  `pkg/sdlc/runner.go` never read the field, so they need no edit.
