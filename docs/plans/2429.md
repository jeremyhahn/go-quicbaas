# Plan: SPEC row release-signing-key (#2429)

## Objective

Ship SPEC row `release-signing-key`, the consumer seam for go-xkms#1697.
Release images and their CoRIM are signed by the tenant release signing
key by default (owner ruling 133 (a)); a tenant can name the signing key
per repository (owner ruling 134). The binding lives in go-xkms (shipped
by go-xkms#1705 in v0.64.0-alpha). go-quicbaas re-exports it through
`sdk/go` on REST, gRPC, QUIC, MCP, Unix and embedded, and keeps no
signing-key binding of its own. Folds #1838 (this plan started as
`docs/plans/1838.md` on `row/1838-aq1838`) and PR #2467.

## Blocker (2026-11-14)

The re-export needs go-xkms and go-xkms/sdk/go v0.64.x; main pins
v0.49.1-alpha, held by #1389 (branch `deps/1389-xkms-v0642-qrdb-v051`,
WIP, the build does not pass):

- go-xkms v0.64.2-alpha and go-qrdb v0.51.0-alpha require go-enclave
  v0.8.0-alpha, which dropped MemoryEnclave.Open.
- go-libsignal v0.3.1-alpha, its newest release, still calls Open.

The lane module cache holds only go-xkms v0.49.1-alpha. No code slice can
build until #1389 lands on main; merge main into this row then.
