   QuicBaaS cannot attach the CA itself. The fix is a go-qrdb change that
   passes the option's CA into the sealed `Infra`, then a pin bump.
   `make integration-test-init` needs `make build` first (`bin/quicbaas`).

7. **Noise responder static-key seam (#1882)** — P-256 static-key DH
   interface, key held in the key store or TPM (go-trusted-platform#518).
   Test: Noise bootstrap responder test with a key-store-backed key.
   *Blocked upstream (slice 4):* QuicBaaS serves no Noise responder; the
   responder is go-xkms `bootstrap.NoiseServer`. The pinned go-xkms
   v0.49.1 already runs the P-256 suite (`P256StaticKey`,
   `NoiseServerConfig.P256StaticKey`), but takes a concrete key held in
   protected memory, with no DH interface for a key-store or TPM key. The
   seam is a go-xkms change, plus go-trusted-platform#518 for the TPM key.
   Seen on the way: QuicBaaS's REST Noise bootstrap request
   (`pkg/service/bootstrap_service.go`) passes only the Curve25519
   `noise_static_key`, not `ServerP256StaticKey`, so a FIPS client cannot
   bootstrap over Noise through it.
   *QuicBaaS side done (this slice):* the Go SDK re-exports the go-xkms
   P-256 key and suite surface (`P256StaticKey`, `SuiteNoiseNK`,
   `SuiteP256AESGCM`, the key helpers, `EnsureSuiteAvailable`, `SuiteError`,
   `NoSuiteError`, the `ErrSuite*` errors). The REST `BootstrapRequest` now
   carries `noise_p256_static_key` and `noise_suite` into
   `NoiseConfig.ServerP256StaticKey` and `Suite`, and every suite error maps
   to invalid input (400), so a FIPS client can bootstrap over Noise. The
   TypeScript `BootstrapBundleRequest` carries the same two fields. The
   key-store or TPM DH seam itself stays blocked upstream as above. Tests:
   `pkg/service/bootstrap_service_test.go`,
   `pkg/api/rest/handlers_bootstrap_test.go`,
   `sdk/go/xkms/trust/bootstrap/bootstrap_reexport_test.go`,
   `sdk/typescript/test/bootstrap.test.ts`.
