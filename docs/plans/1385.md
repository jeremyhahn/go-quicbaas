# Plan: #1385 nightly worker-image workflow

## Objective

The software-factory worker image is rebuilt and published by a scheduled
workflow in this repository (owner ruling 2026-10-15, option (a)), and the
rule that no other workflow is scheduled says so.

## Where main stands

Since the GitHub move, `.github/workflows/worker-image.yml` (#2329, CA m2479
(4)) already:

- runs nightly at 03:00 UTC and on `workflow_dispatch`;
- builds with `make build-worker-image` from the locked versions
  (`versions.lock`, `pkg/version/toolchain.mk`);
- gates the push on Trivy (`push-worker-image`: CRITICAL/HIGH,
  `--ignore-unfixed`) and on two secret scans;
- pushes nothing when the content tag is already published;
- publishes by digest to a private ghcr.io package.

`TestNoWorkflowRunsOnASchedule` exempts it. Its docs and publish tests ride
#2321.

## Slices

1. **The no-schedule rule records its exceptions** (this slice).
   - `nightly.yml`'s header is where the 2026-10-11 rule is recorded. It
     still says that no workflow carries a `schedule:` trigger. It now names
     the exceptions: worker-image.yml (owner ruling 2026-10-15) and
     automerge.yml (owner hold).
   - `scheduleExempt` is hoisted to a package variable in
     `test/buildgates/ci_gate_test.go`.
   - Test: `TestScheduleExemptionsAreRecordedInNightlyHeader` fails while
     an exempt workflow is not named in the header, and passes after.
