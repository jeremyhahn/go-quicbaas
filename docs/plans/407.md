# Plan: #407 conditional factor enrollment (sdk/iam)

## Objective

A downstream one-time identity claim (go-trusted-platform's admin-claim
ceremony) can be made atomic across processes that share one qrdb. The SDK
offers a conditional factor-add. Of two concurrent enrollments for the same
(user, factor type), exactly one succeeds. The other returns an exported,
documented typed conflict error, not a duplicate row and not an internal error.

## Upstream state

- go-qrdb#655 shipped the primitive (closed 2026-10-16). In
  `go-qrdb/sdk/go` v0.56.0-alpha, `transport.AuthFactorAddRequest` carries
  `IfNoActiveType bool` and `ExpectedFactorSetVersion *uint64`. A refused add
  returns `ErrFactorConditionFailed`.
- go-quicbaas pins `go-qrdb` and `go-qrdb/sdk/go` at v0.30.1-alpha, in both
  `go.mod` and `sdk/go/go.mod`, with the comment "held: #1389, the
  go-qrdb/go-xkms stack pin bump". v0.30.1-alpha has no conditional field.

## Blocker

This work can't be built until #1389 moves the stack pin to a go-qrdb tag at or
after v0.55. #1389 is held, and this lane can't override that hold. A
quicbaas-side lock or factor side-table is ruled out by the issue's triage
(locked architecture, docs/00 L8).

## Slices (after #1389 lands)

1. `sdk/go/services_security.go`:
   - Expose the condition on `AuthFactorEnrollRequest`. It is an alias of
     `qrdbtransport.EnrollFactorRequest`, so check that the new tag carries
     the condition there too. If it doesn't, add an SDK option on `Add` that
     maps to `AuthFactorAddRequest.IfNoActiveType`.
   - Add the exported `ErrFactorAlreadyClaimed`, which wraps qrdb's
     `ErrFactorConditionFailed`, with a doc comment that tells it apart from
     a transport error.
   - Map the condition failure in `authFactorsImpl.Add` (and on the REST and
     gRPC server paths) to that error and a 409/precondition status.
   - Tests:
     - A unit test in sdk/go: two concurrent conditional `Add` calls for the
       same (user, type) against one embedded qrdb. Exactly one succeeds and
       the other gets `errors.Is(err, ErrFactorAlreadyClaimed)`. It fails
       before the change (both succeed).
     - The integration target of the iam feature, on every transport.
2. FIDO2 `FinishRegistration`: its request type is xkms-owned
   (`xkmstransport.FinishRegistrationRequest`), so the condition needs a
   matching go-xkms field. Out of scope here unless the pinned go-xkms has it.
3. docs/SPEC.md row 11 (`iam`): note the conditional enrollment, and add
   `changelog.d/iam.md` (callers see the change).

## Out of scope

- The pin bump itself (#1389).
- Any distributed lock or claim table inside quicbaas.
- The platform-side swap (go-trusted-platform#170).
