# Plan: #1461 the authorization endpoint authenticates the end user

## Objective

`GET /oauth2/authorize` (pkg/api/rest/iam_oidc.go `Authorize`) authenticates
the end user on the inherited go-qrdb / go-xkms auth chain before issuing a
code, and binds the code to that qrdb `sdk.User` (RFC 6749 §3.1, OIDC Core
§3.1.2.3; CA m533, SPEC oauth2-oidc consumer row, #1503).

## Status: blocked on the go-qrdb pin

m533 puts this on go-qrdb's `HandleOptional` route mode on
`ModuleHTTPRegistrar`. It ships in go-qrdb v0.51.0-alpha (go-qrdb#783). main
pins go-qrdb and sdk/go at v0.30.1-alpha (go.mod: "held: #1389"), where
`apimodule.HTTPRegistrar` has only `Handle` and `HandlePublic`. Until #1389
lands a pin of v0.51.0-alpha or later, slice 1 cannot be built without a
go-quicbaas workaround, and m533 rules that out.

## Slices (in order, once the pin is on main)

1. Route mode. Register the authorize route with `HandleOptional`. Read
   `qrdbsdk.IdentityFromContext`. With no identity, answer `login_required`
   to the redirect_uri when `prompt=none`, otherwise give the login-step 401.
   A presented credential that is invalid is rejected by the chain.
   Tests: anonymous with prompt=none → login_required redirect, and no code;
   anonymous without prompt → 401, and no code.
2. Bind the code. Set `AuthorizeRequest.UserID` and `TenantID` from the
   authenticated `sdk.User`. Tests: an authenticated authorize issues a code,
   and the exchange returns tokens whose `sub` is the qrdb user. Update the
   refusal that `TestOAuth2Interop_AuthorizationCodePKCEAndRefresh` asserts.
3. Tenant checks (coordinator's acceptance criterion):
   (a) at Authorize, a client whose `TenantID` differs from the user's tenant
   is `invalid_client`, answered directly and never redirected;
   (b) at the exchange, `authCode.TenantID` that differs from the client's
   `TenantID` is `invalid_grant`.
   Tests: a tenant-A user against a tenant-B client, on both legs.
4. SPEC: in the oauth2-oidc row, drop the seam's "waits on the go-qrdb row
   and tag". Add changelog.d/oauth2-oidc.md, since callers see the change.

## Out of scope

- The pin bump itself (#1389).
- Any go-quicbaas login page or session layer (options B and C, rejected).
