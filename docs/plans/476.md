# Plan: #476 dead pre-#475 PIV admin factors

## Objective

Before #475, the init ceremony's `--admin-factor piv` stored a PIV admin
factor whose `Credential` is the certificate PEM bytes, with no
`SPKICredential` and no `cert_pem` metadata. Such a factor never
authenticates. Re-enrolling writes a second factor, so the operator sees two
PIV factors labelled `init ceremony PIV (slot 9a)` and cannot tell which one
is dead.

Ruling 191 (DS-3821, 2026-10-26) adopts the recommended option, option 1:
an explicit operator cleanup command. Boot migration (option 2) and
docs-only (option 3) are not taken.

## Detection (exact, not heuristic)

A factor is dead when all of these hold:

- its type is PIV;
- its `Credential` decodes as a PEM `CERTIFICATE` block;
- `Credential` is not `SHA-256(cert.Raw)` (`iam.MTLSCredentialKey`) of that
  certificate.

A factor written by the current persister (`pivAdminFactorRecord`) never
matches, because its `Credential` is the 32-byte digest, not PEM.

## Slices, in order

1. **SPEC row** (this slice): the iam row in `docs/SPEC.md` states the
   cleanup command, its exact detection and that no boot path rewrites
   credential rows. No test: a docs change.
2. **Detection** in `pkg/iam`: `IsLegacyPIVCredential(factor)` per the rule
   above. Unit tests: a pre-#475 row (PEM credential) matches; a current
   row (digest credential plus SPKI) does not; a non-PIV factor does not;
   a PIV row whose credential is not PEM does not.
3. **Cleanup verb** composed from go-qrdb's auth-factor service: list a
   user's factors, report the dead ones, revoke them only when asked
   (`--revoke`); the default is a dry run that prints the dead factor IDs.
   Served through `sdk/go` on all six transports. Tests: unit test of the
   verb over a store seeded with one dead and one live PIV factor (only the
   dead one is revoked, the live one still logs in); per-transport tests.
4. **CLI**: `quicbaas auth factor prune-legacy-piv --user <id> [--revoke]`.
   Test: the command against the embedded transport lists then revokes the
   dead factor; `make integration-test-iam` drives it on every transport.
5. **changelog.d/iam.md**: operators see a new command.

## Out of scope

- Rewriting a dead row in place (option 2): no boot path mutates
  credential rows.
- Any change to the current enrollment path (#475 already fixed it).
- A go-quicbaas factor store: the factors stay go-qrdb's.
