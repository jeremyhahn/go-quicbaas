## Sleep sweep in the files this PR changes (lane-verify Codex finding)

Done: pkg/cache (expiry by backdating entries, `expireNow`), mock_l2,
pkg/rag/watcher event_test (event order instead of 1s windows), pkg/ha
partition (counted probes), pkg/cluster info, pkg/security coverage and
encryption, pkg/service objectstorage_admin, pkg/util/retry (cancel inside
the attempt), pkg/ollama (handlers block on the request context),
pkg/api/websocket/subprotocol stomp (SUBSCRIBE waits on its RECEIPT).
Remaining: pkg/iam/storage_pool_test.go (7; observables are
`Stats().HealthChecksClosed` and friends, `lastUsedAt` is atomic),
pkg/iam/batch_processor_test.go (20), pkg/watchbridge/watch_bridge_test.go
(13), sdk/go/transport/grpc/transport_test.go (8). The sleep in
pkg/service/embedding_service_test.go is simulated provider latency, the
thing the test measures, not a wait. The repo-wide sweep is #448 slices 2-5.
The unit tests of every swept package pass: cache (with and without the
integration tag), ha, cluster, security, service, util/retry,
api/websocket/subprotocol, and rag/watcher and ollama, which build only
with `-tags rag` (`make test-<path>` has no rule for nested paths, so these
ran as `go test -tags rag`). In storage_pool_test, the sleeps at the
max-lifetime, idle and refill tests wait for a connection to age;
`createdAt` is a plain field the maintenance goroutine reads, so those need
an injected clock or a backdating hook, not a direct write.
