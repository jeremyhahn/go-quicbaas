# Plan: SPEC row oci-registry (#1684)

## Objective

Serve the OCI distribution registry at `/v2/` from `pkg/ociregistry`,
re-homed from go-trusted-platform (gtp) with its history and tests, with the
referrers API; blobs and metadata through the go-quicbaas object-storage
service (go-objstore re-exported); authentication by mTLS workload identity
and by TPM attestation through go-xkms peergate (re-exported), attestation
required by default. Detail: `docs/service-plane/architecture.md` § OCI
registry. Folds #1348.

## Slices, in order

1. **Re-home with history.** gtp's `pkg/registry` history is split
   (`git subtree split`), rewritten under `pkg/ociregistry/` and merged with
   `--allow-unrelated-histories`. The package is renamed `ociregistry` and
   builds in go-quicbaas: gtp-only imports (`pkg/api/grpc`,
   `pkg/crypto/aesgcm`, `sdk/go/services/registry`) are replaced by
   go-quicbaas packages or removed with the gRPC adapter until the SDK slice.
   Tests: gtp's own unit tests pass in `pkg/ociregistry`.
2. **Object storage.** A `Storage` backed by go-objstore through the
   object-storage service replaces the file storage; metadata (manifests,
   tags) as objects. `LocalKMSClient` is removed; layer encryption uses
   the platform KMS. Tests: the storage contract suite runs on the objstore
   backend (memory adapter).
   Done: `ObjectStoreClient` keeps blobs, manifests and tags as
   objects of the object-storage service (keys escaped to object
   paths; the registry acts as the system tenant), and the catalog's
   prefix listing now honours its cursor so listings page.
   `SDKKMSClient` wraps each layer's DEK with a platform KMS key through
   the SDK KMS and crypto clients (the layer digest is the AAD);
   `LocalKMSClient` is removed, and a failed key lookup no longer mints a
   key: only a missing key is created.
3. **Referrers API.** First, gtp's `/v2/` handler
   (`pkg/webservice/v1/rest/registry/ocidist.go`, with its tests and upload
   limits) moves to `pkg/ociregistry/distribution` (done; copied at gtp
   `34ba92bb`, gtp's logger swapped for `log/slog`). Then
   `GET /v2/<name>/referrers/<digest>` (OCI distribution
   spec 1.1) with `artifactType` filtering, from manifests' `subject`
   (done: `Registry.ListReferrers` walks the digest-keyed manifests;
   `artifactType` falls back to the config media type;
   `OCI-Filters-Applied` set when filtered).
   Tests: push a manifest with a subject, list it, filter it.
4. **Authentication.** mTLS workload identity through the auth chain, TPM
   attestation through go-xkms peergate re-exported in `pkg/xkms`;
   `RequireAttestation` defaults to true. Tests: no identity → 401,
   unattested peer → 403 by default, attested peer → 200.
   Done: `distribution.NewAttestedGates` builds the /v2/ gates: a verified
   client certificate's SPIFFE URI is the workload identity (none: 401); with
   `RequireAttestation` (on by default) a request needs a session or fresh
   evidence over a nonce from `POST /v2/_attestation/challenge` (else 403).
   The peergate attestor plugs into `ociregistry.Attestor` after the pin bump.
5. **Serve and integrate.** Mount at `/v2/` on the node's REST server; SDK
   `Compute().Images()`; CLI; `make integration-test-ociregistry` drives
   push/pull/referrers on every transport. SPEC row marked shipped, #1348
   ticked.
   Done: `distribution.NewRegistryHandler` composes the challenge route, the
   gates and the distribution routes into one handler; the REST server mounts
   it at the root `/v2` (`SetOCIRegistryHandler`; 503 until a node injects it).
   The SDK client `sdk/go/client/images` speaks the /v2/ API (blobs,
   manifests, tags, referrers, attestation session) and a wire test drives it
   against `NewRegistryHandler`.
   Open: the SDK `Compute().Images()` accessor, node wiring (after the
   peergate pin bump), the unified-server mount, the CLI and the integration
   target.
