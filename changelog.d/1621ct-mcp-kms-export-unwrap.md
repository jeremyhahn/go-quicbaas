### Fixed

- KMS ExportKey and UnwrapKey over the SDK MCP transport now call `quicbaas_kms_export_key` and `quicbaas_kms_unwrap_key` and return the KMS client's typed `ExportKeyResponse` and `UnwrapKeyResponse`. The wrapping algorithm and export format are always sent, so an AES-KW request is never replaced by the server's AES-GCM default. A request missing its key ID, wrapping key ID or wrapped material, with a negative version, an algorithm, wrapping algorithm or format the server has no name for, or with an UnwrapKey description (the tool cannot carry one) is refused with InvalidInput before any call. A result missing its key ID, with a missing, empty or malformed `wrapped_key`, or naming a format or algorithm the client has no value for, is a typed Internal error (#1621).
