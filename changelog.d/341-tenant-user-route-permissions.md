### Security

- The REST routes under `/api/v1/tenants/{tenant_id}/users/` no longer take a `tenants:*` grant inherited from the first path segment. User CRUD takes `users:create`/`list`/`read`/`update`/`delete`, the same grants as MCP's `quicbaas_iam_user_*`; role grants take `roles:assign`/`roles:unassign`; MFA, sessions, account links and GDPR consent take `users:read` or `users:update`; MFA factor removal and GDPR deletion take `users:delete`; GDPR export takes `users:read`. Before this, `tenants:create` was enough to issue MFA backup codes, grant roles and start a GDPR deletion. A tenant admin who holds `users:create` can now create users, and a principal that holds only tenant-lifecycle grants can no longer reach any user route. The gRPC `FederationService` account-link RPCs (`LinkAccount`, `GetUserLinks`, `UnlinkAccount`) move from `tenants:*` to `users:update`/`users:read`, the same grants as their REST twins. Roles that relied on `tenants:*` for these routes need the `users:*` or `roles:*` grants added (#341).
