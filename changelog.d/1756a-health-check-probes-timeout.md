### Fixed

- The integration stack's storage gate now reads each backend's health as Compose reports it (`docker inspect` of the Floci, MinIO and Azurite healthchecks) instead of running `curl` inside the Floci and MinIO containers, whose images have no curl, so a healthy stack no longer fails the gate before any test runs. `health_check.sh` bounds the PIV login request with `--connect-timeout` and `--max-time` set from `QUICBAAS_HEALTH_TIMEOUT`, and a node that accepts the login and never answers fails the check naming that node instead of hanging it (#1591).
- `health_check.sh` rejects every curl transport error on the PIV login, not only the timeout: a transfer cut mid-response (curl exit 18) after a 200 status and a complete `access_token` no longer counts as an accepted login, and the check fails naming the node, the URL and the curl exit code (#1591).
- Every newly fatal integration readiness gate now has a failure test: `health_check_test.sh` fails liveness, Raft readiness, the PIV credential files, read health and the gRPC and MCP ports one node at a time, and checks the diagnostic names the gate and the node and no later phase runs. The `integration-test` and `integration-test-cluster` wait loops (gRPC, MCP, storage, Ollama, nodes 1-3, AddNode, node4) moved into `test/integration/wait_stack.sh`, and `wait_stack_test.sh` (run by `make check-workspace-script`) times each one out against stubs and checks every Makefile call stops its target (#1591).
- `wait_stack.sh` keeps a wall-clock deadline: the time spent probing counts against each gate's timeout, a probe that succeeds only after the deadline is a timeout, no sleep runs past it, and every curl call and `compose exec` is bounded by the time left (at most five seconds). Three nodes whose probes each hit the five-second limit no longer stretch the 120-second readiness gate to about 720 seconds (#1591).
