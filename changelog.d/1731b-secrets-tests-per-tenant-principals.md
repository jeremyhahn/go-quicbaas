### Fixed

- The secrets integration tests now store each tenant's secrets as that tenant's own principal. Before this fix every store ran as the shared test principal but named another tenant ("tenant-1", "tenant-a", "tenant-b") in the body and the X-Tenant-ID header, which the server rightly refuses as cross-tenant access. The gRPC and Unix isolation cases also ran as one principal, and the gRPC client sends no tenant ID, so they never compared two tenants. The test helpers can now issue a principal for a named tenant (`NamedTenantPrincipalID`, `NewNamedTenantHTTPClient`, `NamedTenantGRPCCredentials`) and release it when the run ends. Every isolation case writes as two principals and asserts that the other tenant cannot read the secret; the gRPC and Unix cases also assert that it cannot rotate, disable or delete it (#1731).
