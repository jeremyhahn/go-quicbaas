### Fixed

- The Go SDK's MCP KV Put, Get and Delete now reach quicbaas's KV service through the new `quicbaas_kv_put`, `quicbaas_kv_get` and `quicbaas_kv_delete` tools, so an entity written over MCP has the same canonical, tenant-scoped key REST and gRPC use, the request's shard reaches the service, ids above 2^53 stay exact (every uint64 is a decimal string), and a service failure is an error rather than a miss. The old raw-key path through go-qrdb's `qrdb_put`/`qrdb_get`/`qrdb_delete` is gone (#2114).
- The Go SDK's MCP policy Create, Get, Update and List now report a policy as enabled unless its spec, the response or its `spec_yaml` sets `enabled: false`, as REST and gRPC do; a policy created from `spec_yaml` alone no longer comes back with `Enabled=false` while its rules are enforced (#2114).
- The unified listeners trust the operator CA (`iam.mtls.tls_client_auth_ca_file`) and the PIV CA (`iam.piv_login.ca_file`) again. Those CAs were being added only to the REST server's private copy of the TLS config, which no listener serves, so operator and PIV client certificates from a CA other than the platform CA failed the handshake. They now go into the server TLS config the listeners serve. That config is replaced copy-on-write, so no pool a listener is already using changes (#2113).
